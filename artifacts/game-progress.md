- Deterministic story events: visitor, guardian choice (`host|observe`), apprenticeship/self-study, departure, rumor, return and two distinct scene ending buildings.
- Automatic `observe` outcome if player ignores the event; no blocking story path.
- New save key `little-haven-jianghu-v02` retaining v0.1 key untouched; offline step bounded.

- Node 22 simulation: 9/9 tests passed locally.
- DOM ID/reference scan: no missing referenced elements.
- npm dependency install unavailable in current isolated workspace; Vite/TypeScript production build delegated to GitHub Actions CI before merging.

- Visual composition and 3D performance need browser evidence.
- Shortest-path graph and collision avoidance are not yet implemented, only deterministic route waypoints.

# Sprint 4 · 修雨、复河与建筑/人物动作精修（2026-11-03）

## 执行顺序与用户要求
- 首先编写 docs/V04_MODEL_MOTION_RIVER.md（先于实现）；之后实施 H1/H2 和三项美术模型/动作的可玩升级。
- 不改 world.minutes、玩家两条分支、机缘、建筑 ID、localStorage 槽位与先前已通过的自动化验收。

## 发现的确定性问题
- weatherArt.ts 的雨条位置曾为 baseY + t*speed，导致纵向运动为 +Y，确实是在向上升。
- village.ts 旧河是 1.81 宽、地表附近的半透明窄 ribbon，河岸没有断面；旧线部分节点 x=8.5/z=±11.8 超出椭圆岛边缘，前景存在被裁剪/不明显的问题。

## 实施模块
- weatherMotion.ts：downward -Y 位移，落到底部后回卷；weatherArt.ts 调用统一位移计算并暴露世界 Y 取样供浏览器连续帧验证。
- riverArt.ts：重新取样中心曲线并调整南北端入/出岛位置，同步河床/坡岸/浅滩/石块/沿水纹（季相配色），桥下贯通；岛前缘增加落崖瀑流与泡沫。
- architectureKit.ts：复用屋脊、檐托、框窗/格栅、双扇木门、石阶、前廊，主酒馆和四类民居分别装配。
- characterKit.ts：职业背包/斗笠/衣袍分层和饰物，保持原角色职业和画面规模。
- characterMotion.ts：行走步态、双手劳动、搬运、采摘俯仰、织布、钓鱼收竿和分段练剑；关节动画以连续秒插值。
- people.ts：保留人物点击 ID，重建可分别旋转上身/头部/膝关节的摆件式关节模型；动作从模拟 activityId 派生，暂停时不自行推进。
- batchStatic.ts/people.ts/buildingRenderer.ts：给动态关节内部的静态几何合批，保持已被动画代码引用的 robe Mesh 独立，避免销毁共享 BufferGeometry。

# Sprint 5 · 「真正活着的村庄」首轮垂直切片

## 决策与美术方向修正（2026-11-03）
- 用户指出：追加零件不等于模型设计；动作波动不等于练剑；静态村庄加几个道具不等于生活生长。
- 因此本轮不是继续修饰旧建筑，而是落地三种**占地、体量、道路用途不同的未来**，并为正式动画资产准备 clip 规范。
- 设计入口：`docs/V05_LIVING_VILLAGE_VERTICAL_SLICE.md`。源技能：<https://github.com/CloudAI-X/threejs-skills/blob/main/skills/threejs-animation/SKILL.md>。
- 该技能官方示例以 Three r186 说明；仓库目前使用 `three@^0.180.0`。本轮只采用 r180 已支持的 `AnimationClip` / `AnimationMixer` / `NumberKeyframeTrack` / `AnimationAction.crossFadeTo`，不盲目复制新版 API。

## 实际代码
- `villageGrowth.ts`：按日推进的轻度村庄经济与长期发展。木料、粮食、交流、劳作、繁荣度和世界选择均可存档；无人干预则选择田园共居。
- `world.ts`：与旧江湖故事分离的三路村庄成长和纪事；旧 v3 JSON 缺新字段时创建未来邀请，不改原剧情与两个存档槽。
- `villageEvolution.ts`：完整的三套未来土地用途，逐级显现地基、木架、主建筑、次生建筑：石桥商路、河畔鱼市、果园小屋。
- `carvedTerrain.ts` + `riverArt.ts`：按同一条样条曲线让浮岛上表面下切，水面确实低于两侧地形；测试走独立的地形高度查询。
- `heroClips.ts`：阿青 idle、walk、sword-form 关键帧与 Mixer，握剑支点随手臂转动；用 crossFade 切换。
- `people.ts`：阿青停止使用原 `Math.sin` 训练姿态，新 Clip 控制命名关节；其他村民暂保留职业程序化动作。
- `main.ts` / `index.html`：三个选择在守谷机缘中出现，实点一次有效；状态显示在守望录；新建筑可点击、可查看劳动日/资源/落成由来。

## 第一轮量化证据
- 旧季度/剧情回归、三路模拟推进、默认自主发展、旧 v3 保存升级和 clip 关键帧验证已进入 Node + Chromium 自动测试。
- GitHub Actions `41591450656` 已通过代码/模拟/桌面移动端 WebGL 检查，并产出三条路线两年后的截图。截图发现当时画面刚好是**雨夜 00:01**，且侧栏遮挡村庄右部，无法作为美术品质认证。
- 当时三路全画面取样差值约 2.28 / 2.84 / 2.52，属于可量化但不够强烈的画面差异。随后扩大三条路线的土地使用与建筑群，并改为固定晴天白昼、关闭浮层的对照图。
- 当前背景性能开销约 628–685 draw calls，不符合 AAA Graphics Builder 建议的桌面 300、手机 150 的起始参考值。场景仍有性能负债。

## 不能宣称完成
- Three.js `AnimationMixer` 已用于角色，但**没有凭空出现专业绑定 GLB**；角色依然是先前的分件几何，必须另做高品质角色网格、衣摆拓扑、蒙皮绑定和动作美术审计。
- 三路建筑采用语义不同的体量布局，尚非最终手工雕琢的模型资产；必须继续克制追加配件的冲动。
- 当前河槽地形有真实的顶点高度下沉，但浮岛侧壁仍沿用旧挤出外壳，没有全面的断面拓扑重做。
- 两年三分支截图在新版日光条件下完成对比、以及低端安卓真实 GPU FPS 尚待最终验收。

# Sprint 6 · 从“贴木头”切换到形体重制（2026-11-03）

## 以用户实际秋雨截图为出发点
- 酒肆原来存在主体屋顶与附加 Kit 屋顶重复、多个标准民居用同一个盒子轮廓、人物胸前背后硬板、村庄主体多年不变。
- 河流当前已经可见，近期美术优先级不是再替换水面，而是保存桥/河岸的清晰空间关系，同时重做城镇主体。
- 完整设计与验收标准：`docs/V06_ART_REBUILD.md`。

## 实际调用的 Three.js 美术技术指南
- 阅读仓库 threejs-game-director、threejs-aaa-graphics-builder、visual-scorecard、authoring-recipes、technical-art、shader-cookbook、threejs-debug-profiler 和 threejs-qa-release visual-test-harness。
- 此轮选择程序化 authored shapes + 现有 AnimationClip/Mixer 联动，未调用外部收费模型 API，也未声称已有专业 skinned GLB。

## 代码改动
- `villageBuildings.ts`：用一体曲面双坡顶、连续檐口、实体山墙、共同材料语言与不同房屋比例替代旧的“房子 + 装饰屋顶”。酒肆由主厅、偏置阁楼及侧厨组成，成熟后整体扩建而非附着一层漂浮的假楼。

# v0.4.4-C · 真正可见的「一块田与留下的种子」（PR #16）

## 目标、产品边界与 Skills

## 已实现的系统与证据

1. `livingFates/seedTrial.ts`：真实共同田间工作的 pair+garden 键，≥8 小时共事与双方田间经验，先实际支付 1.2 份粮食种子；在下一季前两人分别花 ≥5 个排他劳动小时，完成后只为这块菜圃建立持久 +6% **实际收获倍率**；中途停耕／工时不足则真正中止且不退粮，不释放免费收益。

6. 自动化：新增 `tests/seed-trial.test.mts` 6 项场景；桌面浏览器在独立真实世界中模拟出资格，保证真实试种后保存并回载检查 3D 标记及历史，而不会把虚构工作小时写进剧情卡。原旧谷、开荒首屋、三年生长、手机、旧存档回归保留。

- **实现**：真实非创始居民从自己住处沿 A* 合法路径到茶棚，独占下午一小时，才可以办理有物资成本的交换或热茶；低供给、没有人到达、选择清静时不派发货物。相同居民真正接待同一旅人两次后才留下永久熟客台账，从下次离谷算起把普通商路等待缩短两日，不赠送资源。
- **可见**：乡邻有端茶动作，茶棚档案记录实际工时/熟客，人物手记写具体谁认识谁，低频镜头可定位当事人。旧 v0.5.1 的匿名已发生交易能继续读档，但不追认它由谁招待。新增六年与反伪造测试、浏览器 1440×900 / 390×844 回归；已通过最终 108/108 项模拟及桌面、390px 手机 Chromium 和构建验收，PR #20 已合并 main。
- **后续**：独立物流和货物分类、家族与外部战乱、采矿/冶铁、较自然的肢体动画及低端 GPU 优化尚未实施。

- **兼容**：存档主格式与槽不变。旧版所有已到村的鱼保持原貌，仅补零值物流台账；恶意量、人员、站点和时间记录拒绝导入。
- **QA**：[PR #21](https://github.com/mastercook777/Little-Haven/pull/21) 已合入 main（squash SHA `8d633ebd5fae4f8f76c800c44ff411bd2aa45a5f`）。[CI #41954573323](https://github.com/mastercook777/Little-Haven/actions/runs/41954573323) 验证 111/111 模拟、TypeScript、Vite/Pages 构建、Chromium 1440px 与 390px 手机、成熟村庄渔获实运及经典模式回归全部通过。线上部署进度仍以最新 Pages workflow 为准。
- **仍未做**：跨多小时路径与持续搬运、木料粮食其他品类、路网拥堵和生鲜腐坏，低端安卓真机性能实测。优先观察每年渔获送达总量与年四-五茶棚供给是否因独立运输工时发生失衡。

# v0.5.4 · 山居焕新：经典美术复用（PR #22 已通过完整 CI、合入 main）

- **原因**：开荒村落建造逻辑已有实存、实路、实工时，但建筑多仍是直坡屋顶+方块门窗，人物靠刚体臂腿+小色块，保护带树冠长期不换季；整体观感不及 v0.3 经典观察版。
- **落地**：直接复用经典版 `buildMountainRoof` 一体弧面、共享瓦材和雪层；将原保存地块的宽/深/高度作为唯一形体约束。山居正面重新制作双扇木门、纸窗木格、檐下连接件、吊灯及瓷坛，按建筑 ID 稳定生出生活物件差异。粮仓拆去多层叠箱屋顶改用同源经典瓦顶，增加木壁/通风窗。静态立面用现有 `batchStaticSubtree` 减少 draw call，不处置跨楼复用的基础几何。
- **人物与环境**：三位开荒者及后来乡邻沿用同一 ID 与实际岗位/路径，但三维形体改为经典 `dressCharacter` 连续衣摆、披布和身份帽子。两个现有松木保护地块替换为季节阔叶，春花夏荫秋黄冬枝；未向林缘新建地块乱种不可清除装饰树。
- **原则与风险**：未把既有村庄建模或固定路线移入新模式；不新增 3D 市民、不改存档、不改变物流和社交世界状态。住宅木阁和建造阶段必须仍被看见。最终 [CI #41963981991](https://github.com/mastercook777/Little-Haven/actions/runs/41963981991) 已 115/115 模拟、TS/Vite/Pages、桌面和 390px 手机 Chromium 全绿；新增真实冬季 4/4 成熟曲面瓦顶积雪、零建筑开局和五年 12 人/11 设施/3 木阁仍正常。[PR #22](https://github.com/mastercook777/Little-Haven/pull/22) 已合并。开局渲染 493 draw calls/42298 triangles/87 geometries（旧版 444 calls），第五年 1063 draw calls/75442 triangles/268 geometries，仍高于移动端建议预算。需人工查看近景四方向、冬雪及真实低端 Android FPS；专业绑定角色和道路交互动作另期。
