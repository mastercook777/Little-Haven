# 守望谷 · Sprint 5「真正活着的村庄」垂直切片

> 2026-11-03 · 设计先行，再以单一模拟时间、可点击守谷决策、可见的地块变化和角色动作展示验证方向。
> 本文以用户审美反馈为最高优先级：**不再给旧模型堆积木；村庄的整体轮廓必须因不同人生与守谷选择发生变化。**

## 1. 玩家体验
玩家不是直接指挥每名村民的镇长，而是见证山谷在生活需求、自然环境、乡邻劳动和少量守谷选择下改变。一条河能催生商路、渡口或农圃；选择不干预时，乡邻也会自主选择稳妥发展方向。

### 约束
- 不引入可购买的硬货币或每天点击收菜的工作；世界继续自动发展。
- 保留阿青「留宿／顺其自然」的独立江湖故事分支，两条分支与三个村庄发展方向可组合。
- 保留 v0.2 / v0.3 两个存档槽和 JSON 导入；本轮新字段在旧 v3 自动补齐。
- 无外部付费模型 API 或 LLM 运行成本； Three.js 美术与动画依赖本地代码/以后可替换的 GLB。
- **观察结果必须是结构性差异，不是替换几块装饰道具。**

## 2. 三条空间发展线（同一开局，两年后截图必须不同）

| 路线 | 初因 | 早期施工 | 建成后主要改变 | 次生生活方式 |
| --- | --- | --- | --- | --- |
| 山桥商路 `bridge` | 河水上涨，商旅绕行 | 加固桥墩、木料、施工架 | 新石桥、东岸商棚及旅舍，东西向人流和高低层建筑增加 | 人口/贸易/名望增加，商贩往返桥市 |
| 河畔渡口 `ferry` | 河流成为生计 | 下水栈桥、晾网和船料 | 水岸渡船、鱼市与舟棚，沿河产生连续建筑区 | 捕鱼/物产和临水活动增长 |
| 田园共居 `grove` | 邻里优先自给 | 整地、菜圃与花木 | 梯田果园、新院落与小屋，村庄向西南扩张 | 生活满意度与安定人口增加 |

- 第一年晚夏出现一次「水脉与村路」守谷机缘，提供三个选择，不做选择则乡邻在一个季节内自行转向田园共居。
- 每条发展路线经历 `proposed → foundation → construction → landmark → thriving`；每阶段对地块外形/占地/可见结构产生不同影响。
- 村民每天仍自主劳动，工程随时间和劳力逐渐完成；每季的食物、木料与商贸/渔获以可理解的轻模拟数字反映乡邻经营状况。资源不需要玩家机械收取。
- 不因世界跳季跳年产生额外或遗漏进度；无操作和直接推进应得到相同结局。大量跳年仍需遵守现有安全上限。
- 至少提供两个可追溯的生活后果，进入守望录：决定路线、施工开始、主要建筑落成、聚落成熟。

## 3. 稳定世界数据合同
新增 `src/simulation/villageGrowth.ts`：
- `VillageGrowthState` 含 `choice`、`decisionAt`、`deadlineAt`、`chosenAt`、`phase`、`labor`、`materials`、`prosperity`、`completedStages`。
- `progressVillageDay()` 是纯数据规则，返回因果事件，不修改渲染、DOM 或本地存档。
- `chooseVillageDirection()` 单次有效；无操作在截止日自动决策。
- 旧 v3 world JSON 只添加增长字段，不覆盖剧情和建筑。
- `VillageGrowthState` 均有严格边界，拒绝不合法输入，保护 JSON 导入。

## 4. 有地形的河床
旧阶段仅在完整地表上放一条凸起的水面与斜坡；本轮将山谷上表面替换为根据同一河道中心线计算高度的**连续低多边形地形网格**。
- 河槽中心的地面低于水面，两侧向草地逐渐抬升；水面、河床与桥共用一组曲线坐标。
- 岛屿立面仍保留原几何轮廓，不允许出现单独悬浮的水片。
- 道路、桥、居民工位不得埋入河床；在桌面与移动端对比河槽坡度及多角度连续性。

## 5. 美术与动画方法论调整
### 禁止
不允许以增加一个背部矩形「背包」、前胸矩形「服装」的方式声称重新设计了完整角色造型。不允许以 `Math.sin(t)` 摇手充当完整练剑动作。

### 允许的垂直切片
- 以阿青优先建立可替换的人物演出管线。真正高质量最终角色仍应走统一概念图 → 角色建模 → 绑定 → 关键帧 → GLB 的制作流程。
- 使用 **CloudAI-X/threejs-skills 的 `threejs-animation`** 作为动画技术标准：`AnimationClip`、`AnimationMixer`、`AnimationAction`、clip fading/crossfading、命名骨骼节点、必要的程序化层；支持以后接入 `GLTFLoader` 导入的动画。
- 第一批只做可测的阿青 `Idle` / `Walk` / `SwordGuard` / `SwordCut` / `SwordRecover` 三相练剑和切换。剑要跟随握剑节点；角色重心必须有方向和接地。
- 如果缺少可绑定的真实高质量 GLB，必须明确标注目前是「基于分件模型的 clip 管线」，**不冒称完成骨骼美术资产**。
- 角色大改优先改基础网格、相互体积关系及关键姿势，而不是再贴几层装饰。

## 6. 可玩的操作与反馈
- 「江湖风闻」面板在水脉机缘出现时显示路线 A/B/C 的一次性选择，不遮盖普通剧情；若不回应按时自行选田园共居。
- HUD/守望录显示村庄的实际发展方向和当前建设阶段；点击新建筑可观察建造阶段与原因。
- 流年一季一季推进，每季地块大形态变化、之后跨两年见到完整村落，且重新开档可重复对比。

## 7. QA 硬验收
1. Node 单测：三条路线必然不同、自动选择、阶段幂等、直接快进 vs 多日步进一致、旧档无损导入。
2. Chromium 真实 WebGL：相同 seed、相同视角、同一季节、相近时间，生成 `bridge` / `ferry` / `grove` 三张两年后截图。对比不只看 hash，要检查空间上实际建筑体量差异。
3. UI 点击一次选择后，世界记录/视觉/道具三方同时改变；正常流年、暂停、两个槽位与 mobile UI 回归。
4. 河槽深度采样必须验证：中心 < 水面 < 两岸地表，不只是有水面模型。
5. 动画验证 `Idle→Walk→SwordCut→SwordRecover` 至少四个可区分姿态，过渡不会 snap。
6. 用真实浏览器调试信息报告 draw calls / geometry / triangle，区分高品质和低端机性能预算。
7. 不完成的高品质外部模型/正式 skinned GLB 必须留在残留风险，不算通过。
