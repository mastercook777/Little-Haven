# 守望谷 v0.5 第一轮 · 两年后还有生活（工程执行规格）

> 开始于 2026-11-04。回应玩家反馈：二年左右停滞，守谷人的参与只有三项生存方针。仅第一轮 v0.5 的可玩生产与议事闭环，本文件不宣称完整六分支、战乱和江湖已经完成。

## 产品体验契约

1. **两年后有真正的后续生产**：一间原本不存在的河岸渔棚，具有经安全勘址选出的真实地块、需要木材和工时、专属取鱼岗位和有限季节鱼群；非仅在日志里写“靠河吃饭”。
2. **发展方向不能只是一句装饰话**：原有三个生存方针仍用于前期，新增独立的“村落议事”方向——自理、渔业、田园、木作。居民自治也会逐渐进行其他分支，方向只改变顺序和工作倾向，不永久锁死其他。三个方向分别影响渔棚优先级、粮仓优先级、木作棚工作台试作工时与木材效率。
3. **真正不同的场景**：渔棚／浮晒鱼架、粮仓／谷桶、木坊锯木台由状态驱动。没有施工完成的建筑不能预先显示。河岸渔获库存按季节和完成劳动变化。
4. **增长不只到九人**：若住房、粮水、农田承载力足够，再容纳最多十二位常住乡邻。新增三人各有稳定 ID、真实迁入门槛、日粮消耗与公共活动，不自动送满屋子。
5. **生活方式图谱可查**：以现有真实建筑、居民和采集事实显示节点完成/条件不足，不造“科技点”。用户从村落议事里看到方向的现实条件和已有后果。居民无操作也会继续建设，旧档默认为自治。
6. **可复盘**：多 seed、四～六年连续/季度推进；鱼群有限库存、冬季下降；工艺提升需要木材工时，重复加载不重复加木；所有设施的建造必须走现有 SAT/A*/林地开垦校验。原 v4 与 v3 档保留，严格验证 corrupt save。

## 第一轮实现边界

- **河岸渔业**：有安全可达岸边和渔棚，捕鱼实际将鱼群库存换成村庄 food，额外记录累计捕鱼与岗位，雨/季节限制由已有天气和时钟计算。渔人出工时放下其他工作；显示鱼竿与晒鱼篓。当前食材池暂仍归并在 food，未新增独立食谱和货物运输。
- **田园与储粮**：粮仓消耗真实木材和施工工时，随后全村粮食可储上限提高（不赠送粮食），农业方向优先扩建粮仓，其他方向晚些也可解锁。
- **木作与工具**：木作棚先消耗 4 份储木、居民在真实工位完成 6 小时锯木台工单，才能加速后续真实伐木劳动；非立刻获得工具或加库存。
- **三路并非永久排他**：允许中途改建议，但不删除已投资、已建的实体。早期三项生存建议仍可用，原始开荒三人起点不变。

## 明确留待后续的完整计划

- 真正跨小时装货、返村、入库事务；鱼的独立实物货物与长期发酵/保存食谱
- 商道驿村的客栈、客商交易、正式临时访客与名望、人情与手艺分源声誉
- 石脉、冶铁、学舍、学徒传承和社会命运多分支；完整六分支产业互相依赖
- 复杂历史战乱和武学不自动成为核心；高端动作美术、低端安卓实体 GPU 手测

## 技术与验收

- `PioneerWorld.schemaVersion=4` 与 localStorage key 不动。新增可缺省迁移的 `livelihood` 子状态，含方向、工作台实际木/工时、首次捕鱼记录；旧档从已有可见设施恢复当前状态，不回填不存在的历史事件。
- 资源账统一在小时结算中，建筑使用原 `PioneerIntent`。生产场景只读真实的 `PioneerWorld`，不在 `graphics` 增加资源或居民。
- 依仓库 pin 的 `threejs-game-director`、`threejs-gameplay-systems`、`threejs-game-ui-designer` 和 UI patterns、`threejs-qa-release` 流程，跑 `npm run test:sim`、`npm run check`、`npm run build:pages`、经典与开荒 desktop+390px Chromium smoke。
- 验收重点：自然 2～6 年里出现既有四类外的合法实体；方向可使至少一个后续里程碑时间/产业类型不同；鱼群和粮食库存按真实劳动守恒；选择点击、存档与流年一致。不能用一次截图证明经济平衡、美术和完整路线图全部完成。
