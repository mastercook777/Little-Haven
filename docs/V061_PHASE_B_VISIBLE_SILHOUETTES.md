### 最重要的根因：此前新模型没有进入生产场景
`pioneerVillage.ts` 虽然引入了 `makeV6Homestead`，但一直没有调用，`facilityVisual` 仍以老版 v0.5 工厂创建房屋。这使得原先的屋檐、侧廊、院墙模型**仅在直接单元测试里存在，玩家画面没有用到**。目前已按真实保存的 `parcel.homesteadStyle` 选择 H1/H2/H3/W1 并真正实例化完整住宅/开放木作场。新测试从实际生产工厂调用模型，阻止再次出现静默回退旧屋的假成功。

统计是像素事实，**不是自动美术评分**。这一版外观已能看出茅顶小宅、开放木作场和瓦屋侧廊，但大规模屋宅/邻里视觉仍需要人工验收，不能说已达到经典观察版的美术质量。

### 实际成长与安全合同
- 初始仍为三人/0 座永久建筑/0 座永久院坪，没有为了截图固定铺一座成熟村。
- 田土、宅地、生产作业坪、主路及重复使用的石板来自已建建筑与实际 A* 道路；原河床高度、静态树根、未开发土地仍保留。
- 地表颜色取原河床顶点材质做 deterministic blend，切换季节时不积累，不改地形高度；重开档还原本来的草面。
- H1/H2/H3/W1 必须由运行中的实际 model factory 返回并保存同一个建筑 ID、门向和完整出入口；foundation 不得产生完工主屋。
- 工程正在尝试 `batchStaticSubtree` 的 opt-in 命名保留合批，必须用实际截图 draw calls 回归，不能假定高面数等于更精致。

### 本阶段仍有缺口
1. 真实 H3 仍容易因 5.25×5.0 的安全地块不足而回退为 H1，成熟村里可能重复 3 户茅屋；这是**选址/规模**问题，不应把单纯替换颜色宣传成 H3。
2. 路面分级、场坪与实际屋形目前已看得见，但还没有让居民真正进入自己的小院；私人 A* 保留待做。
3. 园地分带仍偏粗，某些作业场亭顶形制还很简单。下一步应优先处理真实邻里规划 `SettlementCluster`、合法的高低差、住户院落之间的生活关系，避免重回“一轮几百行代码、像素几乎不变”。
4. 静态几何合批后的最终性能与完整 Chromium 回归必须通过后，本 PR 才能申请合并 main。
