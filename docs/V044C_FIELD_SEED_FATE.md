# 守望谷 v0.4.4-C · 一块田与留下的种子

> 本文记录工程纵切片：两位平凡乡邻可用真实共事经验改变一块土地。该切片在 PR #16 开发与 QA 中，**不是**完整版 v0.4.4 或江湖门派系统。

## 1. 体验与分支

观察到两人在**同一块真实菜圃**累计至少八个小时的共同田间劳动，而且双方各有田作实践时，才可能提出留种。现有菜圃「留种养地」运营倾向提高该提议的可能；个别粮仓非常富足、多人长期共农的村庄也能自主试种。只有确实存在的、运营中的菜圃才允许提出；至少十天可供照料的当季时间、可达田地、粮水余裕均为真实门槛。普通人足以做成，不以隐藏武学身份为资格。

- **短期代价**：从全谷存粮真实扣除 1.2 份种粮，计入本日粮食支出；不是 UI 减号或从空气生种。试验开始不会立刻产粮。
- **真实行为**：两位参与者各需要在该菜圃完成五次独立的逐小时试种照料工单，每天安排一天一小时的种植尝试；这些小时完全取代他们的通常采食、建造或其他工作。无法抵达、停耕或口粮严重不足就不计工时；每人同一小时只能结算一次。
- **成功**：跨越统一季节边界，双方工时完成，写入带 effectId 的永久 `FieldLegacy`，仅该菜圃未来**真实采收**增加 6%（现场 crop stock 和仓库容量仍然约束数量）。三年后的丰收不是额外发给玩家的季末奖励。
- **未达成**：粮食紧张或设施停工导致工时不足，则在下一季记为中止，不退种粮、不加产出；人物仍有永久的人生记忆。允许未来在条件恢复且过冷却后重试，最多三次，不会无限触发。

已完成情节不会自动揭示身份，也不凭空新建房屋、道路、人物、门派。

## 2. 数据归属、不可重复与旧档

`PioneerWorld.schemaVersion=4` 以及 `PIONEER_SLOT_KEYS` 不变。附加 `LivingFatesState`：

| 字段 | 用途 |
| --- | --- |
| `farmCoWorkHours` | 稳定 pair + gardenId 键，从已经完成的同园同时劳动事实累计，不按站得近增加 |
| `seedTrials` | 稳定 `seed-trial-[gardenId]-N` 状态机，留种支出、参与者、各自工时、上次工作分钟、应结算季节、结果和事件 ID |
| `fieldLegacies` | 绑定真实 gardenId 的永久田间经验及 +6% 采收效果；只有 `resolved` 才能插入 |
| `appliedEffectIds` | 与 `fieldLegacies` 一一对应的唯一完成事务，阻止季节跳跃、载入、重试重复奖励 |
| `majorMemories` | 写下人员、当季、试验所在地、对应 journal event ID，独立于 160 条短日志，人物离开后仍保留 |

导入 v0.4.4-A/B 旧档时，缺少的四个新增字段**必须同时缺失**才视作旧规范并迁移为空值；已有收入、房屋、原始人物、既往记忆保留，不追认虚构试田。部分伪造字段、假庄稼地、非法人物 ID、提前完成时间、重复收益均拒绝。v0.3 经典模式完全隔离。

## 3. 场景和交互

- 试种有真实状态后才在菜圃模型旁增加小型木牌与试验床，随 `working/resolved/abandoned` 切换；没有试验的普通菜圃仍是原来的造型，不能在开局假装已有苗圃。
- 两人真实照料时间显示为弯腰田作动作，列表显示「试种留种」；田地详情列出参与者、已消耗种粮、各人工时、季节结局、固定产能变化；人物手记也能看到双方曾经共同尝试。
- 用户既可点击真实 3D 菜圃、也能从设施清单进入；手机不需要增加新的悬浮面板。已有「留种养地」按钮仍是建议，不能直接向村民发布强制试验指令。

## 4. 代码与验证

- `src/simulation/livingFates/seedTrial.ts`：资格、工时、季节状态、永久效果、校验和独立原因日志。
- `src/simulation/livingFates/peopleState.ts`：同一花园实际共同劳动、长久记忆与公开人物检视。
- `src/simulation/pioneerWorld.ts`：统一时间步，工单排他性、菜圃实际库存和持久读档。
- `src/graphics/pioneerVillage.ts`：真实状态驱动的试田木牌与苗床。
- `src/ui/pioneerInspection.ts`、`src/pioneerMain.ts`：可见后果、缺料与长期往事。
- `tests/seed-trial.test.mts` 和 `tests/pioneer-browser-smoke.mjs`：要求真田、真共劳、种粮守恒、排他工时、成功／失败分支、首次效果幂等、旧档迁移和公开 UI。浏览器将走真实开荒模拟，再用专门的充裕粮仓 fixture 验证成功分支的 3D 形态；这不等于宣称所有自然村庄必定成功。

### 本轮 Skill 使用

按仓库钉住的 `threejs-game-director` 协调；`threejs-gameplay-systems` 确认一个可玩可测的因果循环；`threejs-game-ui-designer` 约束人物/田地检视的移动端可读性；`threejs-qa-release` 要求 Node 模拟测试、编译、Pages 产物、Chromium 桌面和 390px 手机实际测试。这版新增的是现有 Three.js 细小构件，不需要外部生成素材、3D 模型 API 或图片服务。

## 5. 仍然未完成

1. 长期师徒／家族/旧兵伤者故事线；各个技能的复杂来源还没有完整模拟。
2. 田间苗圃的角色精准动作、独立跨小时运输与门口避让尚需打磨；试种阶段仍沿用现有小时级往返的近似动画。
3. 长期经济需要继续用不同 seed、天气、人口压力做真机与人眼审计；真实设备 FPS、审美评分和 v0.5 产业成长树不在本次完成声明中。

**验收原则**：如果玩家读过十年后这块田的记录，应该能知道哪两人从什么实际共劳开始、为试验损失过多少粮食、花过几个小时、何年哪季成功或中止，以及为何现在这块田比另一块田多一点收成。
