# 守望谷 v0.6.0「山谷新生」——整体美术与聚落空间重构

> **状态：设计方案，尚未开发；绝不能作为已上线成果宣传。** 2026-11-10，依据用户最新五年成熟村庄冬季截图以及此前秋夏截图的反馈制定。
>
> **重要授权**：可以放弃现有开荒 v4 存档兼容，重新做地块、建筑占地、组团、道路和地形；**不得自动删除旧数据，也不得影响 v0.3 经典观察版及其存档**。新开荒世界仍从三人、一处篝火、零永久建筑开始，用户可通过流年重看成长。

## 1. 产品承诺与前轮反思

**山外是江湖，山里是家。** 一群南宋末年的避乱者和隐居人，因为粮食、河水、亲友、手艺和真正的工作路线，从营火慢慢长成一座有人生活的小山村。

过去的 v0.5.4–v0.5.6 大多优化“程序生成了多少种模型”，而不是“同一张默认全景里，村庄是否已经不同”。实际成熟村庄仍然是相似的青瓦白墙、几个孤立木棚和田地、近乎平坦的地表；尤其冬季统一的浅色雪地把道路与建筑层次冲淡。**仅有新屋脊参数、新摆件或 133 个 CI 测试通过，不构成美术升级成功。**

本次目标应在玩家**不看代码、不看 UI 标签、不放大相机**时成立：

1. 住宅、生产设施、临河场所可由整体轮廓区分，而不是换色区分。
2. 能看见“这两户共用一条巷子/小院”“粮仓与田地相互依赖”“渔棚属于河岸工作区”。
3. 房屋真实大中小错落，有前院、台基、偏屋和建造后的年岁痕迹；不再只是在相同的约 3×3 格子里反复套屋顶。
4. 路、土地、石基、院子、草地和冬季薄雪能区分；悬浮岛仍明亮、安静、易于观察。
5. 同 seed 的第一、第三、第五年，**旧有的空间主体**能够随真实施工、修缮、扩建发生可感知变化，而不是只增加外围摆件。

## 2. 美术方向：宋末山乡生活的手工感微缩世界

### 2.1 保留与不做

- 保留明亮、干净、柔和 NPR 的 Low-poly 微缩浮岛、正交旋转镜头、桥和河谷；不是超写实、脏灰末世废墟或者复杂古代城市。
- 木、石、泥、竹、草、青瓦是主要形体材料；衣服、工具和风化来自实际住户/职业。**不要靠官式飞檐、红灯笼、龙纹或寺庙形制证明“武侠”**。
- 方向 A「江湖中的村庄」仍然是唯一默认玩法；武者和江湖势力是长期人物命运的少数结果，不先预摆酒肆、门派或道馆。
- 不让新模型数量、物理渲染技术或更高多边形数成为“美术进度”的衡量本身。

### 2.2 一致的材料体系

| 区域 | 新美术语言 | 当前应淘汰的问题 |
| --- | --- | --- |
| 草屋、小户 | 暖土墙、深浅不同的草/木片顶、低木门、少量房前物 | 每户都用同样青瓦白墙 |
| 普通农户 | 小青瓦、木柱、暖粉墙、石基、半围小院 | 只是屋顶高低变化 |
| 较稳定的人家 | 主屋+偏屋+内廊的不同体量、院落/门台高差 | 在原统一地块里硬塞一片侧屋 |
| 木作、粮仓、渔棚、茶寮 | 开放度、台基、生产场地、临河/临路关系各自鲜明 | 又出现四座结构相同的小亭子 |
| 一般地面 | 草坡、紧实黄土、碎石脚径、田土、院中踩踏痕、河滩砾石 | 均匀一张平板 |
| **冬季地面** | 屋顶迎风积雪、草面不均匀薄雪、仍可见的黄土路/墙根石基/灶坪、暖木阴影 | 大面积几乎纯白，建筑与路融成一片 |
| 雨天 | 檐下干湿交界、院角水痕、湿润但不糊掉纹理的土路 | 用统一灰雾遮盖材质空白 |

**优先顺序必须固定**：全村剪影与地势 → 建筑和院落主体 → 地表材料 → 光照/阴影接地 → 生活道具 → 粒子/天气。已经实现的叶片、水花、瓦面雪不是本次重构的主要成果。

## 3. 空间架构从“散装地块”改成“有生活关系的聚落”

### 3.1 三层生成与责任

| 层次 | 建议接口 | 真实作用 |
| --- | --- | --- |
| A · 地形使用分带 | `ValleyZone` / `TerrainPlan` | 找出可步行的台地、林缘、岸坡、田地潜力、崖边禁布与河道水面 |
| B · 村落组织 | `SettlementCluster` | 根据已有房屋、需求、道路和地形规划**邻里组团 / 田园仓廒 / 木作后场 / 河岸渔业 / 乡路茶寮** |
| C · 完整生活地块 | `HomesteadPlan` + `BuildingEnvelope` | 主屋、偏屋、院落、台阶、真实入口/工作点/未来扩建地的整套占地和可见几何 |

原 `pioneerGrowth.ts` 在固定宽深的小型地块上扫描和打分，是美术同质化的核心瓶颈。即使 v0.5.6D [PR #28](https://github.com/mastercook777/Little-Haven/pull/28) 把评分改成朝真实乡路，也不等于解决**建筑体积与院落组织**，因此这次要直接重写选地合同，不是在其上多添参数。

**重要禁止**：`SettlementCluster` 只表示可发展的潜在生活片区，**不会自动画出任何已经建成的房子、院墙或田园**。必须由真实住户/生产需求、物资、工时和安全可达的工地逐步把候选规划变成现实建筑。

### 3.2 五种可辨别的空间关系

1. **营地/村心公共坪**：最初仅三人围火与临时柴堆；渐渐形成真实公共灶、坐处、围火场和一条被踩出的短路。村心留出呼吸空间。
2. **住宅组团**：两三户有自己的门、可达小院，也可能共享晒场/院墙/巷道；还有偏坡独户，村庄不能排成统一网格或全屋面向镜头。
3. **田园与粮仓**：几块田有坡度变化、相通的畦道、取粮前坪，真实粮仓不是独立放在无关位置的瓦顶箱子。
4. **木作与河岸生产**：木作是一座开放工作场；渔棚靠合法河岸，有真正晾网与搬鱼篓路径；都不得侵占住宅门口和水面。
5. **山路茶寮**：发展成熟后依真实乡路出现一处有停步空间的半开敞茶亭；访客需要有真实主事居民和带成本的接待活动，不能冒充常住人口。

主次路径分为公共主路、住户短巷、田间小径、河岸作业路。路线由真实使用与必要的付费修路演化；**初始不刷完整石板街**。路线不许被围墙、额外偏屋或台地挡死。

### 3.3 地势与地块尺度可以真正推翻

目前 `PIONEER_VALLEY` 的浮岛中心约 x=-1.7，半径 x=18.5、z=12.2；`carvedTerrain.ts` 除河床外基本平坦。v0.6 允许重新调整岛屿轮廓、开拓可建区域及**2–3 级可行走缓坡台地**，让院落、田块和临河作业区有高低关系。

- **建筑先定完整体量和院落面积，再申请地块**，不能反过来拿老房子的固定地块把更大建筑压扁。
- 台阶和地面高度必须和 A* 导航及人物脚底高度一致；房屋先有石/土台基，不能在起伏地形上漂浮。
- 河道仍以共享的 `creekCorridor.ts` 样条/岸带为真实水面约束，保留零树根入水、零建屋入河和真实可达。
- 新住宅扩建允许申请**邻接的额外土地**。小地块装不下大院时就建小户、合法清地后再盖，或暂缓施工；不可侵占原路和邻居地。
- 村庄长到多年后也不应卡在单一中心圈：可沿现实可走的道路在安全缓坡建立**第二个住户小组团**，不是凭时间凭空生成一片新村。



## 4. 建筑体系重做：不同户屋、不同占地、不同生计

这是**要重制的主体**，不是 v0.5.6 已有 C1–C4 模型的说明。

| 美术族（设计名） | 必须改变的主体轮廓 | 完整用地的组成 | 成立的真实条件 |
| --- | --- | --- | --- |
| **H1 茅顶小屋** | 窄而低的一室小屋，草顶厚檐，土/木墙 | 主屋 + 小小门前坪 | 初来者或资源紧缺的小户仍可住人 |
| **H2 瓦屋农户** | 宽正房，青瓦坡顶，半矮院墙与一处晒架 | 主屋 + 半围合院落 + 可通行正门 | 安稳定居的普通家庭 |
| **H3 廊院农舍** | 主屋、侧偏房、短廊形成可识别的不对称组合 | 复合屋基 + 真实小院 + 可扩建净空 | 额外木料/工时与真实邻接土地，不能免费多床 |
| **H4 高台旧宅** | 依靠地形的石台基、高侧墙、阶梯门口与修补瓦 | 屋基 + 石阶 + 狭长院落 | 合法缓坡位置且楼门与道路可达 |
| **木作场** | 开敞主棚 + 高低不同的侧储木架与宽作业坪 | 木作房 + 晒木场 + 工人操作点 | 真木匠、木料、锯台工艺阶段 |
| **粮仓** | 高脚仓、可辨仓门/通风、卸粮木台 | 仓体 + 卸粮前场 + 田路 | 粮库实际扩容与搬运需求 |
| **渔场** | 轻棚、独立晒网、低桩栈台和可达临水操作位 | 河岸禁水带内侧的作业坪 + 真实鱼篓路线 | 捕鱼与运鱼仍分别占工时，鱼不能凭装饰增加 |
| **茶寮** | 面路而开的高檐茶亭、坐处、旗牌与歇脚坪 | 小茶亭 + 有边界的路口活动场 | 真道路、材料、接待居民、旅客 |
| **农田** | 平畦、台田、阶梯畦、编篱田在不同土地上混搭 | 可走畦径 + 田埂/灌水小沟 | 实际农地库存/收成与播种状态 |

**约束**：
- H1–H4 是**因家庭条件/地势而选的房屋类型**，不是所有住户必然从 H1 升级 H4，也不添加不合语境的豪宅/宫殿。
- 初始三人仍没有任何永久建筑。所有落成物必须有登记中的施工阶段：勘地→备料→地基→梁架→成屋。需要更多的房屋主体/院落就必须花费相应物资/工时。
- 旧模型 Kit 可拆取有价值的弧瓦、木构、衣饰、天气位置函数，但**不能强制所有新屋继续占原有 2.5–3.1 单位的矩形地块**。
- 用实际屋顶几何和基础台地生成雪与檐滴；不能出现房屋变大了、雨还按旧高度悬空落下。门、围墙、晒场、侧屋完整进入 SAT/复合 polygon 防穿模系统。

### 4.1 院落必须有“住着人”的意义

`HomesteadPlan` 至少包含真实门口、可达小路、主屋外廓、户外生活点、可碰撞院墙/门洞、生产工具或柴水堆、未来扩建可能区。共享院子必须有实际住户或工作组关联，不能画出第二个没有人住的院子冒充增长。

年岁由**已经发生的事件**驱动外观：新屋木色与瓦面较整齐；长期有人居住就有踩踏门前坪；condition 随年月/雨雪变旧；**真的花钱修房**才能出现补梁、补瓦和更干净的局部；付费扩建会改变院落或房屋的主体轮廓。空屋不能假冒炊烟/晾衣，没做锯台不能摆高级工具，粮仓和鱼篓的视觉内容要由真实库存控制。

## 5. 地表、季节和生活痕迹必须同源

### 5.1 五层地面

从底层到表层建议统一为：
`terrainHeight`（真实高差）→ `landUseMask`（草/土/石/田/岸）→ `trafficWear`（真的走过形成踩踏路）→ `plotOverlay`（院落/台基/作业坪/田埂）→ `seasonWeather`（雨湿、雪霜、落叶）。

地貌不再只是“一个草地 Mesh + 上面铺路 + 天气着色”。坡脚有水痕，常走的路是压实土，木坊脚下有碎木屑，粮仓台阶是石/木，田埂土色偏深。所有层次在真实高程和河流样条下结合，不能复制第二套假水岸。

### 5.2 冬景专门验收

最新用户截图的问题不是“雪不够多”，而是**冬天太浅、太平、太统一**。v0.6 必须让冰雪依地形/屋檐/树荫/行路分布：
- 迎风屋面与草坡积雪，脚径、取水小道、灶坪、工作前场有踩踏裸土；主要道路即使有雪也可辨边界。
- 木梁和台基保留暗部接地影，不让阳光/曝光把瓦面冲成白顶。
- 田地冬季有残茬与局部霜土，不被一张整齐的纯白平板覆盖。
- 春夏秋不靠一个色相滤镜。秋叶仍从真实树位落到真实地面，雨滴溅落和积水应避开河内/室内。

## 6. 程序架构与先后依赖

### 6.1 继续复用哪些“真系统”

保留 `PioneerWorld` 自治居民/职业/资源/天气年岁、原始三人、季节流年、有限库存、工时排他、真实住房和人口条件、砍树清地、A* 实路、捕捞→待运鱼篓→另一次劳动搬运→口粮、粮仓存量、茶棚真实接待和来客记录。保留 v0.3 经典模式作为隔离的另一款完整玩法。

**不复用的限制**：`pioneerGrowth.ts` 固定用途地块大小、在旧小矩形里强行塞所有建筑的美术惯例；当前 `facilityVisual` 大型集中过程式模型；只通过增加变体 hash 来描述建筑个性的架构。

### 6.2 建议新增职责（仅方案，不是已创建代码）

| 模块建议 | 核心输出 | 与旧代码关系 |
| --- | --- | --- |
| `settlementPlanner.ts` | 有身份的邻里组团、公共路、生产场区候选布局 | 取代单体“随机扫描+打分”作为高级规划入口 |
| `homesteadGeometry.ts` | 主屋/偏屋/院落/平台/围墙**完整 footprint** | 扩展 `pioneerParcelRules.ts` 的 SAT 约束 |
| `terrainPlanner.ts` | 地势台阶、可建地/农地/岸带同源采样 | 演化 `carvedTerrain.ts`；溪流几何与河岸禁区必须一致 |
| `pioneerNavGraph.ts` | 2.5D 可达门口、台阶与实际道路宽度、真实生产工作点 | 建立在 `pioneerPaths.ts`，不可绕过 A* |
| `buildingCatalogV6.ts` | 不同整体体量的住宅/工作场屋形和成本参数 | 允许淘汰原 C/W/F/G/T 的统一占地与简单 hash |
| `homesteadScene.ts` + `buildingWeatherSockets.ts` | 一份真实 BuildingSpec 生成模型、雪瓦、雨檐、生活挂点 | 拆分 `pioneerVillage.ts`；图形不变更模拟状态 |

概念类型（不是可直接编译的源文件）：

```ts
type HomesteadPlan = {
  id: string;
  clusterId: string;
  kind: 'home' | 'workyard' | 'granary' | 'fishery' | 'tea' | 'field';
  styleId: string;            // 施工前冻结形制
  buildingFootprint: Polygon; // 主屋、偏屋、屋檐及未来扩建
  yardFootprint: Polygon;     // 院落并不是第二栋免费屋
  entrance: WalkPoint;
  workSockets: WalkPoint[];
  roofSockets: RoofSocket[];
  terrainPad: { y: number; stairs: WalkPoint[] };
  buildStage: 'survey' | 'foundation' | 'frame' | 'complete';
  requestedBy: number[];
  condition: number;
};
```

规划先输出需求、形制与真实完整外廓，再验 SAT/水岸/坡度/道路/关键资源可达。最后才安排材料支付和劳动施工。任何步骤失败都不得进入已建名录；扩大院落不应和建小草屋同成本。

## 7. 放弃旧 v4 开荒存档兼容，但不随意删数据

1. 新版建议用 `little-haven-pioneer-v06-slot-1/2` 新前缀及独立版本号；首次进入从三人零房开始。**旧 v4 导入不能伪装成新复合用地**。
2. 旧的 v4 本地键值**不自动删**，v0.3 经典键和旧谷入口完全不动。新版清楚提示“地形和院落系统已更换，需要新开局”；旧导入可显式提示不兼容，而不是导入到半损坏的场景。
3. 新版仍提供双槽、导出、重开；v0.6 **内部**的读档、流年和离线必须有一致结果。“允许放弃旧档”不意味着以后每次更新都可随意破坏 v0.6 存档。
4. 当前在审核的 [v0.5.6D PR #28](https://github.com/mastercook777/Little-Haven/pull/28) 最多算过渡版本；真正的 v0.6 以复合院落与组团规划重写选址规则，不能仅在 #28 的距离评分上再加分宣称重构。


## 8. 版本开发路线：先交付一张真正不同的村庄

| 阶段 | 需要实际做出来的交付物 | 本阶段不可替代的完成条件 |
| --- | --- | --- |
| **0 · Art Target** | 旧版真实五年截图基线、村落鸟瞰分区草图、至少三种主体房屋剪影设计、远景主次方案 | 先证明新村庄有**建筑、台地、院落和路**的构图差异，不是新瓦色 |
| **A · 代表性纵切片** | 新地表/台基、一组**由真实施工长出的**住家+院落、一座真正开敞的作业场、一段实际连接道路 | 同一默认远景就能分清新版空间；三人零永久屋开局、材料工时与实际道路不回退 |
| **B · 全村复合用地** | 组团规划 + 不同规模 lot + 可扩建用地 + 新村实际多种子生长 | 第三/第五年真实建筑不是散点，至少能辨认住家小组团和一个生产/田园组团 |
| **C · 全面资产与生活痕迹** | 全部功能屋/田畦新体量、台地/石基/土径、真实住户旧化修补、四季的地表分带 | 冬季不再白成一片；建筑主体增长和院落变化不是随机摆件 |
| **D · QA、性能和上线** | 严格的新旧对照图组、四方向视觉审计、桌面/移动及真机诊断、最终发布记录 | 无视觉否决项且真正人工审美通过，才可称为 v0.6.0 美术重构 |

**阶段 A 最小纵切片是核心转折点。** 不允许一开始耗时重绘整个岛，最后仍看不出差异；先让一户人家和一座工坊成为可信空间，再扩大到全村。不能为了对照图好看，在 seed 42 直接按固定脚本摆好成熟村庄；所有结构都从模拟真实落成。

## 9. 验收必须新增独立的“观感闸门”

### 9.1 真正的 Before / After

- 使用**同种子 42**，各自真实模拟到游戏第 5 年；以用户最后一张 v0.5.6C 冬季成熟村全景为视觉基线，并另外在浏览器保存旧版同相机参数的夏/冬截图。
- 同样的正交相机位置、旋转、焦距、1440×900 画布、时间与季节；v0.6 新版必须输出同规格五年图。另补 390×844 手机 viewport。
- 各做**0 年/1 年/3 年/5 年**四个成长点，夏晴、秋、冬至少三季，另有雨天；第二个 seed（推荐 20261103）重复第 3、5 年来反证没有“硬编码一座村”。
- 默认全景、从后面看、左侧、右侧四方向，检查屋顶、偏屋、台阶、墙门、河岸和真正居民道路；必须至少有一组**剥去颜色的灰度/剪影图**，防止靠光照/雪颜色掩盖构图同质。
- 对照截图库可按 `artifacts/evidence/v060/`（待创建）组织；每张图写清 seed、年份、时间、季节、相机、分辨率、版本/commit SHA、真实建筑数量和来源。没有真实截图就不能声称过了美术验证。

### 9.2 独立美术判定（代码 CI 无法替代）

至少一位**没有实现模型的观察者**（优先玩家）看真实游戏截图与可旋转场景。必须确认：

1. **不看颜色与 UI**，五年远景也能辨认至少 3 个显著不同的建筑整体轮廓与不同用途的活动空间。
2. 同屏能指出至少**两处院落/道路/建筑构成的可生活关系**；有公共小核心和疏密组织，而不是 11 个单独小模型。
3. 从 1→3→5 年能看见至少一处**已经存在的家庭/公共用地/主路主体**因真实支付施工发生明显形体变化，不止增加花盆和灯笼。
4. 冬景瓦屋、台基、黄土/石路与雪坡的材质边界能辨清，不靠整体高曝光/灰雾糊平场景；人物在地面有可读接触。
5. 道路能走、河里无树、房屋与院墙不穿模，四方向都合理；建筑点击和生活道具不互相遮挡。
6. **盲对照**：遮掉版本号，让观察者说明哪张更像“有人居住、缓慢长大、因生计组织起来的宋末村庄”，并能指出至少三处**主体空间/建筑**区别。若做不到，判定本阶段美术**未过**，即使 150 项测试全绿也不例外。

### 9.3 工程守恒与性能

- 保留模拟不变量：三创始人零房、资源与劳动总量守恒、住房容量/迁居条件、森林真实砍伐、河鱼捕捞与独立运鱼、茶棚真实来客、A* 通路、天气、流年/日步进确定一致。
- 新增测试：复合占地 SAT、院门净空、台阶导航高度与人物脚底、合法修缮扩建、所有设施工作点通行、同 seed 多种子确定性、v0.6 两槽/导入导出；v0.3 老谷不能被 v0.6 地形影响。
- 运行 `npm run test:sim`、`npm run check`、`npm run build:pages`、`npm run test:browser`，真实 Chromium 桌面与 390px 手机、控制台无错误、交互可点。截图不是仅对比 `Box3` 和 `archetype count`。
- 最新 v0.5.6C 的五年场景约 **1073 draw calls**（此前 CI Chromium 渲染统计，不是 Android FPS）。v0.6 必须披露 calls/triangles/geometries/textures/阴影/DPR，并对细部重复构件做共享材质/批绘/实例化；**暂定五年桌面目标先压至 700 calls，再尝试 500 calls**，是目标不是承诺。移动端实际帧率须在硬件上单独测。
- 如果视觉目标只靠增加几百件独立 Mesh 达成，且性能无法解释/降级，则不能视为完整可发布版本。

### 9.4 一票否决情形

只要发生以下任一项，即便 CI 全绿也不能宣布 v0.6 美术重构完成：新旧远景肉眼难分；仍是同尺度灰瓦小屋排布；预摆“假成熟村”；大屋不付真实材料/工时；院墙挡门或鱼篓凭空生成；雨雪把一切染成纯白；只在默认镜头不穿模、转到侧面模型相交；没有真实相机/年份标定的对照截图，或没有人工独立评价。

## 10. 第一个实施 PR 的确切工单

只做**Phase 0 + Phase A 的小而完整纵切片**：

1. 从 v0.5.6C（或其已确认基线 commit）抓同 seed=42 真实第五年夏/冬的标准镜头、建筑清单及 renderer.info；把用户最新冬景作为评审参照，不能把上传图片冒充已生成 repo 文件。
2. 根据相同视角完成一份清晰的分区/高差/主次街道草图与三款真实屋型**远景剪影目标**。先确认新画面和旧画面差别，不直接写几十个程序化工厂。
3. 实现必要的最小 `HomesteadPlan`、台地和入口规则；只先从真实自治流程建出**一座住家 + 前院 + 一段可走路径 + 一处邻近工作场**。其他设施暂可沿用旧资产，但须如实注明没做。
4. 完成代表性建筑的全体量建模、材料/地表接地、可点击实体、季节雪与檐滴；老屋模型与新屋不能在同坐标同时显示两层瓦。
5. 跑真实 0/1/3/5 年和第二 seed；给出 **Before/After 近远景与去色剪影**，经独立美术审查，若差异微弱**优先重画主体**，不准先堆数十个生活道具。
6. 模拟/类型/构建/双模式浏览器全部通过后，才合 PR 到 main。**这次不再以“新增多少模型种类”作为 PR 标题的完成依据。**

## 11. 已冻结的决策、边界和实施参考
