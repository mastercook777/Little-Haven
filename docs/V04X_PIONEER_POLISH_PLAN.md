# 守望谷 v0.4.x · 开荒纪元打磨与生命力补完计划

> 状态：**待实施的产品／技术规格与开发任务单**，不代表对应功能已经上线。
> 来源：2026-11-04 用户提供的第一间棚屋近景与第 4 年聚落实玩截图；对照 `main` 的 v0.4 Phase A+B 实现。
> 原则：保留放置、居民自治、同种子可重现、真实资源消耗与 v0.3 经典模式。**先修可信度，再增加体量；不能通过按年份刷新预制建筑假装生长。**

## 0. 版本目标和用户体验契约

**目标一句话：** 同一座山谷，开局看见三人砍木、点火、搭棚；多年后可以选中每一间屋，知道谁使用过它、谁修过它、材料从哪来；土地、林地、路网和村民生活都留下过程痕迹。

### 每个时间尺度玩家应该看到什么

| 时间尺度 | 观察反馈 | 守谷人参与（不点也能发展） |
|---|---|---|
| 30–90 秒 | 人物从家/营地走到实际资源点，采集/返回/存放；工地有真实阶段动作 | 点人、点屋了解为何这样做 |
| 一段日夜 | 晨起、出工、运料、做饭、用餐、散步、睡眠有变化；晚间确实使用房屋 | 可修改一项工作/生产偏好，不微操个体 |
| 一个季度 | 菜圃种植／收获、林地局部稀疏与恢复、房屋修缮痕迹、村心设施演变 | 看见一项值得回应的生活议题 |
| 第 1–4 年 | 居住与工坊地块扩出安全核心区，有村路、明确功能分区、住户故事 | 从真实可达的发展方向中选择倾向 |
| 更长时间（v0.5） | 生计职业分化、矿石/渔获/商贸形成闭环；文化与名望吸引人口 | 在生活方式树上解锁分支而不是手点建筑坐标 |

**两条反面标准：** 不能只靠人口和建筑数变大来代表成长；不能让九个居民长期在 HUD 全部显示「回家休息」而世界里看不出他们生活过。

## 2. P0 必修：先把当前版本变成可信的小村（v0.4.1）

### P0-01 修正棚屋和山居的建筑结构（先只做 1 间，验收后推广）

**目标：** 玩家一眼知道哪里是屋顶、屋脊、檐口、立柱、墙和入口，坡面不会反扣，木料不会悬浮。

- 建独立 `PioneerBuildingKit`：**本地轴**统一 `+Z` 为入口、`+Y` 为屋顶方向，明确屋脊方向和每类建筑的正面。
- 从 `shelterVisual` 抽离「柱—梁—椽—面板—芦苇覆盖」节点；屋面几何用同一坡面方程产生端点，不能让屋板和芦苇装饰分别靠手写 Z 旋转和 Y 平移。
- `cottage` 与 `wood-yard` 使用不同 archetype：山居有真实完整围护墙、门槛、门扇、可用内门口，木作棚为通风开敞工具架而非换色房屋。
- 修复建设相态：地基不提前出现屋顶；梁架阶段能看见骨架；完成才有完整屋面和家具。
- 模型尺寸必须同步进 `VillageParcel` 和建造检查：**真实屋檐、台阶、后棚、门口、屋面最外点**全部有合法净空；不能用碰撞代理比实际模型小掩饰穿模。
- 使用现有 `villageBuildings.ts`、`V06_ART_REBUILD.md` 的成熟中式屋面和形体经验，但不可直接套入旧谷预制房。
- 旧化表现不再是一个漂浮补丁贴片；新旧/修缮状态切换材质、瓦片和木构修补，视觉随 `condition` 变化。

**验收：** 雨/晴、前/后/左右、旋转 0°/90°、地基/梁架/完成/旧化/修缮六种组合均截图；任何坡面无穿顶、浮梁、板条交叉、门被檐遮、柱梁不接；检查由 `Box3` 转世界坐标后的净空与入口可达。

### P0-02 点击房屋／工地／资源点，获得真正的实体详情

建议从**建筑详情竖向浮层 + 选中描边**做一个完整切片，先不要上复杂的按钮菜单。

- 鼠标 hover 高亮、点击选中；触屏单击选中，拖动旋转仍操作相机；点空白取消，快捷键 Esc 返回。
- Raycast 识别 Mesh 祖先的 `buildingId`，不能把柱、屋顶等零件当作独立建筑 ID；道路和背景不抢焦点。工地也通过 `intent.id` 选中。
- 详情面板字段：名称/用途、建造年季、完成时间、耐久及修缮、住户与工作人员、可容纳人数、正在执行的任务、当前供需、暂停原因、材料和工时溯源、因果记录。
- 建筑运营初版只需轻量操作：**当前启停／一个优先级／一个生产偏好**；操作作为结构化事件进入模拟，不要在 DOM 点击里直接更改资源。
- 特殊对象：营火/村心、菜圃、林地、工地有各自详情；未解锁选项必须写明原因。
- UI 容量：桌面浮层避开岛屿中心；390px 手机上底部抽屉并留可操作 3D 区域，所有点击目标为可触达尺寸；无鼠标 hover 也可用。

**验收：** 点击真实山居后，名字、入住者、耐久与存档同一 ID 对得上；暂停/恢复后该建筑工作确实停/恢复；切槽、存档刷新、缩放、旋转、触摸拖拽不出现错误选中；旧 v0.3 模式无回归。

### P0-03 营地升级为村心，而不是四年后仍然野营

- **状态 0 临时营火**：三人草席、简易火堆，雨天可见狼狈。
- **状态 1 安家火塘**：第一间遮蔽落成、至少三人有家后，草席清退，石圈/围坐木凳出现；仍可保留小火。
- **状态 2 公共灶台**：稳定农产/人口满足公共用餐需求后，锅灶、备餐架、避雨小顶与村民烹饪动作出现。
- **状态 3 村心空地**：公共生活设施形成后，火塘不再独占视觉中心；铺装、公告栏、集会场地替代，节庆/聊天可以承接。火可熄灭或进入灶台，不得是第一天的原始大火。
- 建议添加 `VillageCommons` 稳定实体，类型及 `stage` 入档或可从持久化建设事件完全推导；升级需要工时/材料/实际设施前置条件，不是到第 N 天自动换模型。
- 它占用最初营地的保留地块，更新阶段时同时重新做邻近道路、碰撞和通勤起点核验；不重复占地和凭空赠送物料。

**验收：** 同 seed 同发展状态下，同一阶段的外观和资源消耗一致；第 3–4 年满足阶段条件后不会还剩三张草席；空谷/失败建设时不会提前出现广场。

### P0-04 一套可看见的「日常生活」，而不是一直回家休息

- **模拟任务**：睡眠、起床/整理、烹饪、吃饭、备料/送货、工作、屋前休憩、邻里交谈、夜间返家；「做什么」和「在哪里」都写进状态。
- **排班层**：`residentNeeds → chooseTask → reserveDestination → path → action → result`，一个居民/一个时间点最多占一份工；站位和路径必须能被建筑使用容量允许，避免六人挤在一个门口。
- **事件层**：家/菜圃/木作棚/火塘里可出现阶段性的取用与生产，不是只在场外加库存。无料时人物停止伪造锤击。
- **表现层**：最小职业动作集——搬柴、抬木、耕地/收菜、做饭、席地吃饭、围坐聊天、进屋/出屋、修补屋顶；先精修少量职业动作再复制更多职业。
- **长期行为**：每天允许少量基于性格/职业/关系的生活偏好，日志保留因果而不是流水账；夜间 6 个名字一致显示「回家休息」可以成立，但 UI 应说明已入夜，并可查看白天活动记录。
- **任务中转**：住屋/营地是位置，资源点是位置，生产设施是位置；不要把每个小时的行走动画重新从路线起点循环（现有 `phaseHour` 每小时出返程属于 P1 待修问题）。

**验收：** 1× 连续观察两个完整昼夜至少看到工作与非工作活动、真实进出屋；夜间大多数人有家可归，绝不出现跨河、瞬移进屋或无路线产出；快进与实时时钟结果一致。

### P0-05 木材供需、饥饿应急与有限库存的可解释性

用户第 4 年截图出现 **食物 0、木材 16.3、饮水 5.4**，不能只当成 UI 问题。

- 增加可复现「四年谷」诊断存档，按每人/每职业统计日粮需求、采集收益、耕作收益、林木再生、运输时间、仓储容量、施工占用工时。
- 最低生存应急优先于新建筑：当口粮/饮水低于约定警戒线，居民优先调整采食、耕种与送货；不可一边长期饥饿一边继续建三间新屋。
- 不增加「凭空刷新食物」的保底作弊；自治须通过真实可达的资源点、劳动和种植恢复。
- 为过量人口和单一作物设置约束：粮食短缺影响迁入，连续短缺可触发贸易求援（仅 v0.5 解锁后）或调整食物来源；入户并非免费增产。
- 明确产出放在采集任务**完成之后**结算，不在村民出门瞬间同步加库存；允许单次出产由抽象数据池决定，但视觉必须能跟上。
- HUD 显示至少「近一日粮食净变化 / 短缺原因 / 下个任务」而非一排裸数字。

**验收：** 4 年×3 种方针×3 seed 的增长曲线有解释；灾年允许缺粮但有短期应急和明显风险，不得无尽原地零库存仍按常态迁入；每笔采集与消费守恒。

## 3. P1：让开荒过程被看见（v0.4.2–v0.4.3）

### P1-01 真伐木 + 局部林地疏密

**数据层建议：** 林区 `ForestPatch` 是聚合库存，不对每棵树结算木材；视觉树由 `seed + patchId + visualIndex` 稳定采样，记录少量视觉状态 `standing / chopping / falling / stump / regrowing`。

- 村民选一个可以到达的林地伐木站位；走近 → 举斧/敲击 → 树摇动 → 达到事件阈值向避人方向倒下 → 木料/树桩可见 → 运回真实仓储点。
- 由树林库存比率驱动活树密度/树桩/幼苗数量；无需每棵树对应唯一真实产量，不要因此诞生数百个存档单项。
- 伐倒必须对应已扣除或已完成的 **采伐任务事件**；仅打开/刷新画面不得重复播同一棵倒树或追加木材。
- 林区季节与数年恢复；树桩可消失、幼树恢复；清林获得可建设净地但减少近期产能。
- 成长回报：看见林线后退、清出的地逐渐形成路和建筑，长年后允许远端林区接续生产。

**验收：** 伐木完成事件和库存变化一一对应；连续十次采集有抽象树木减少、倒地、搬运反馈；重载还原库存与疏密；树倒不穿过房屋/人物/河道。

### P1-02 地图从“固定小岛”变成有开垦过程的大山谷

这不是把当前岛屿所有坐标乘 1.5，更不是直接让外围从一开始就铺满房屋。

- 地形、河流、水位、浮岛/坡崖边界、导航网格、地块规划、植被/资源点、相机视锥 **统一引用 `WorldTerrain/RegionRegistry`**，不再由多个文件维护不同半径。
- **三圈体验**：营火周边可直接使用的安全小地块；需要清灌/伐木/平地的缓冲圈；资源丰富但交通和工具成本较高的外围区。
- 扩张的规则：首次调查 → 合法可达 → 清障（林木/石堆）→ 形成路径 → 地基开建；未经开垦不能直接把新屋放在长满树的位置。
- 资源区保护：林地砍光换到更多空地有代价；保留连片树林、河岸与未来渔业/矿山的生态与视觉身份。
- 地图占地增大后，镜头仍可看到初始营火—河流—第一屋这个戏剧中心；提供平滑局部聚焦和回到全岛，不能导致开局全部元素缩小难辨。
- 旧 v4 存档迁移：保留现有建筑的 world 坐标、稳定 ID、道路与各资源；在新的 region 中重新验证，与旧物重叠要显式修正或进入安全兼容层，不准静默移动已建屋。
- 性能：林木远端使用 LOD / InstancedMesh；导航分区/缓存；不能把每一帧都变成全岛 A*。

**验收：** 同种子不同开垦次序导致 **空地形状、林木疏密与建筑范围**实质差异；第一年仍多留白，第四年有清理出来的用地和通往外围的路；桥/河/建筑净空与存档位置一致。

### P1-03 道路通勤、搬运、生活站位补全

- 居民从真实当前坐标到下一个目标，通过路线分段持久推进；按游戏时间和走速消耗工时，途中不计入目标点工作产出。
- 施工木材、采集食物、修缮工具等明确「出发/抵达/取货/运回/交付」事务；不要只在伐木地点加全村库存。
- 路面继续由实际脚步使用形成，但行走累积必须排除 `registerPioneerTrip` 在分配任务和每小时工作中重复计数的风险。
- 路段交汇处增加最小站位避让和停留，门口前预留排队/等待节点；无需先做复杂群体寻路。
- 渲染更新不应销毁共享 Geometry/Material 导致切档后元素失效；这是现有 `replaceWorld` 资源生命周期需实测排查的技术债。

**验收：** 一段完整的「出屋 → 林地伐木 → 背木 → 木作棚入库」有真实移动、库存变化与路径使用；两人不会永久卡在同一窄口；切槽 20 次不丢模型/贴图。

### P1-04 视觉风格再统一

- 采用「明亮克制的中式山野微缩、可信手工构造」：材质分为木、瓦、草、石、土、布；先统一建筑比例/屋脊，再给纹理、污渍和光照。
- 已积累的 V06 屋顶／角色动作／河床构建作为**优先复用来源**，先盘点清单及授权，再决定哪些组件迁入新模式。
- 每类建筑建立 reference 近景（前 45°、背 45°、顶视）＋中景剪影；室外可见的门、台阶、屋顶最少精度要求先固定。
- 自然变化包括：可砍伐树、草地退让、脚印/土路、雨后湿土和檐滴、菜畦随季节改变；必须对应真实状态，而非用色彩蒙版取代生产。
- HUD 排版优化：电脑上左侧导语不裁切，右侧状态栏可折叠，手机底部信息不会挡住整个岛；农作/建设/生活反馈优先在场景内发生。

**验收：** 以用户截图中的棚屋近景、第四年总览为回归基准，提供修改前后相同镜头；人物和建筑风格有统一的体块语言，多角度无漂浮/倒置建模。

## 4. P2：玩家参与和发展选择（v0.4.4）

### P2-01 三级轻决策，不做强制手动城建

1. **谷级方针（长期偏好）**：生存、住房、生产、商贸、探索等方向只在真正解锁后显示；重心影响优先级和资源分配，不直接指定未来房屋的坐标。
2. **建筑运营（局部低频）**：例如菜圃偏自给／留种，木作棚偏建筑料／修缮，房屋偏家庭／空房待客；具体操作先做 1–2 类且有真实产出差异。
3. **重要议题/里程碑选择（偶发）**：村民达到公共灶台/第一位工匠/外围林区通路等前提时，守谷人可支持某条发展线；忽略也会按居民自身偏好推进，绝不会因为没人点按钮卡住。

**反馈链：** 建议 → 有权限的居民提出计划 → 选择可达地块与工作 → 材料工时 → 设施或生活结果 → 守望录。这条链不得被 UI 快捷操作跳过。

### P2-02 里程碑 UI 与成长节点底座（不先完整实现科技树）

- 新增「村落手账」：分成生存、定居、生产、交通、社区五页，只显示已知、下一步可达和少量已锁节点。
- 每个节点提供「已实现／可推进／缺少条件」状态，点击展示真正的不足（人口、岗位、食物稳定性、木材、合法用地等）。
- 已完成里程碑在世界留下可见记号（路牌、公告栏、灶台升级、村民岗位），而不只是弹窗。
- 方向支持并存和有限分叉；**不会因为选择田园而永久禁止钓鱼或商贸**。完整矿业/渔业/名望体系留给 `docs/V05_SETTLEMENT_GROWTH_TREE.md`。
- 里程碑事件需确定性、幂等、可重放、可跨槽比较，避免流年跳季重复发放奖励。

## 6. 数据边界和建议模块

建议新增（**仅设计，均未实现**）：

- `simulation/regionRegistry.ts`：可建设区域、林木/岩石、河岸和扩张、导航的统一地理合同。
- `simulation/pioneerDailyLife.ts`：角色 `ActivityState`（目的地、开始时间、预计耗时、当前步骤、任务原因），独立于渲染帧率。
- `simulation/pioneerFacilities.ts`：建筑运营模式、容量、工位、当前功能、生产和维修队列。
- `simulation/pioneerCommons.ts`：村心升级的需求/事件/材耗/功能容量。
- `simulation/pioneerForestry.ts`：ForestPatch 聚合库存与由事件映射的稳定可视树状态。
- `ui/pioneerInspection.ts`：选中对象和面板状态（不直接突变权威存档）。
- `simulation/pioneerMilestones.ts`：条件/解锁/结果的幂等节点机制（下阶段展开）。

**重要约束：** `PioneerWorld.schemaVersion=4` 及现有 `PIONEER_SLOT_KEYS` 不可直接改写破坏老档；变更采用已审计的字段迁移器和新老 JSON 比对。旧谷 v0.3 的两槽必须完全不受影响。

## 7. 每个切片必过的验收矩阵

- **档案矩阵**：全新三人营火、第一屋施工中、第一屋完成、第 2 年、用户第 4 年典型布局、不同方针、不同 seed、缺粮、无可用地、读档/导入、两槽来回切换。
- **镜头矩阵**：近景「棚屋屋顶」＋中景「村心」＋远景「四年全村」；0°、90°、180°、270°；晴、雨、冬；desktop 1440×900 和 mobile 390×844。
- **行为矩阵**：1× 连续 10–15 分钟真实时间抽样记录、两昼夜长时流年/持续播放对照，采集运输进出屋和职业任务动画，暂停时无模拟推进。
- **工程门槛**：`npm run test:sim`、`npm run check`、`npm run build:pages`、`npm run test:browser`；建筑净空/道路可达、材料守恒、种子可复现、事件不重复、旧 v0.3 不回归。
- **证据**：固定镜头同 seed 的前后两版图片、模拟时间/相机/seed、浏览器控制台错误、draw calls/triangles/内存、实际设备/浏览器记录；全凭截图不能宣称底层资源逻辑正确。
- **人工判断**：人物路口与伐木是否可信、建筑细节是否成立、左侧文案/右栏是否遮挡观看、四年的成长是否有生活而不只是数目。自动化 CI 无法替代这一项。

## 8. 暂缓范围与 v0.5 衔接

- v0.4.x **不会**一次性加入矿山、铁匠铺、完整渔业、交易经济、商誉、复杂文化树。先保证营火、林地、房屋、道路和基本生活是可观察的、可信的。
- v0.4.4 只预留里程碑底座；v0.5 将围绕**生活形态成长树**而不是传统科技点消耗树：资源、新职业、建筑解锁、名望和移民之间要形成因果闭环。详见 [村落成长树设计草案](V05_SETTLEMENT_GROWTH_TREE.md)。
- 最终北极星：玩家打开第 4 年存档时，即使**不读右侧数字**，也能从村心、道路、林地、屋舍痕迹和人物生活判断这里曾经经历过四年。
