# 守望谷 v0.5.6D「村落有序」· 新村落的生产选址、邻里和真实乡路

> 实施 PR 中：实际发布以 PR #28 的完整 native / Chromium / Pages CI 为准。此阶段只改变**未来建筑候选地块排序和实际入口记录**；不搬迁旧房、不伪造树木/道路/仓储/人口。规范依据 [V056 村居百态](V056_PIONEER_ARCHETYPES_ECOLOGY.md) P2。

## 真实问题与修复边界

此前 `pioneerGrowth.ts` 虽然为开荒模式运行 A* 和完整 SAT，但打分仍调用经典观察模式 `villagePlanning.nearestRoad`，根据**根本不在开荒模式中存在的预设 VALLEY_ROUTES**计算 `road.distance` 与 `accessX/accessZ`。画面展示的是村民真正踩出的另一路网，选址和入口信息却隐性继承了旧版道路位置。越到成熟阶段，房子的朝向越容易与真实道路脱节。

这一轮为 `pioneerNeighborhood.ts` 编制纯数值、可单测的唯一开荒道路源：扫描 `PioneerWorld.roads[].points` 的实际段，计算任意候选入口到真实已保存道路的投影与最近距离。当尚未修出一条路时，**不存在道路**，返回 `null`，绝不生成虚拟经典路线。

## 规则

- **先合法、后美观**：`surveyPioneerPlot` 仍使用先前真实河道与植被 SAT、岛缘、已清开用地、完整可达 A*、**四项真实资源可达性**、完整物资/工时和已付费建筑存档规则，唯一新增是候选合法后排序偏好。
- **房门朝向实际道路**：使用现有 0 / π/2 两种合法朝向，分别按 `pioneerEntrance(parcel)` 的真实世界坐标评估与已保存路网的距离，近门侧排序略优；`parcel.accessX/accessZ` 记录真实入口，取代原先经典预设路线上的虚拟接入点。完整路网仍由 A* 生成和验证，评分不能代替路径。
- **住宅邻里**：若已建成真实住宅，离最近一户约 4.65 米的合法候选有轻量优势；仍允许地形和乡路要求驱使独立家庭远居。
- **生产关联**：木坊更靠真实林地、但离住宅近得过头会有惩罚；粮仓更靠现有菜圃；渔棚更靠真实鱼点，且保留既有河岸距离的强约束；茶棚优先真实通行路径，而不是旧版预设路；菜畦与住房及既有田地形成合理但不强迫成排的邻接。
- **权重受限**：每个功能偏好均有限幅（一般单项 0.45–1.0 分），`neighborhood.total * 0.85` 加在原地形/距离/政策/seed 得分上，避免美观评分让小镇在狭窄合法地形上永远不建设。没有任何新的种子外部输入或帧时钟随机数。
- **旧存档只增不迁**：旧 `parcel.x/z/rotation/accessX/accessZ` 不需要回写，导入保留原状；只在未来主动勘地的新项目使用新打分与新入口。所有真实造楼需求、当事居民、工时、库存和住房容量原样。

## 验收

1. `tests/pioneer-neighborhood.test.mts` 检查空道路时不生成假道路、实际保存道路的段投影、相同地点两种合法旋转房门靠路有优势、住宅邻里和产业位置靠近真实来源。
2. 真实 2 年种子 42 与 20261103 自治生长，保持三人/零房初始；所有**新建永久建筑**均记录了 `pioneerEntrance`，从营地有真实可达路线，读档并没有更改建筑、路线或工时。
3. 全量 `npm run test:sim`、`npm run check`、`npm run build:pages`、桌面 1440×900 与手机 390px 两模式 Chromium，五年人口、真鱼货运与真实茶棚仍然成立。性能指标记录构图成熟村 `draw calls`，并与 v0.5.6C 的 1073 对比。
4. 如新评分使已验证的五年人口/渔业/茶棚/路径出现回退，必须改小偏好权重或撤回，不允许放宽 SAT/伪造资源来使回归“通过”。

**尚未实现**：P3 多年居住修补痕迹、河岸生态分带、更复杂的朝向角度（当前仅两种经过 SAT 的合法旋转），以及低端 Android 真机负载。
