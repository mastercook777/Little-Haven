# 守望谷 v0.5.2 · 山路故人：真正相识的茶棚乡邻（第一条命运纵切片）

> 基于已上线 v0.5.1 的真实茶棚/来客和 `LIVING_FATES_SYSTEM_V1.md`。这不是剧情卡片：熟识必须由真实劳动与可达交通达成，付出实物并改变村庄往来，过客不自动迁居、无江湖门派。

## 为什么做
茶棚在五年内真接了客，但原模型于到访后两小时在无主事居民劳动的情况下自动交换物资；八名外来人的名字虽然重复，但村中没人记得谁曾经坐过同一张桌。这使茶棚在成立后趋于重复的库存换算，缺少人物命运。

## 本轮承诺的真实因果
1. 茶棚要有一位**已存在的常住居民**在一次独占的下午工时内沿实际 A* 乡路到达茶棚接待。如果村民忙于缺粮/缺水保命、道路断开或无人可服务，访客**短暂停留但没有交易和招待**。不能同时记同一个小时的农田/伐木/接待成果。
2. 每次真实支付的交换或热茶记录 `hostResidentId`、访客姓名/来路、时间、结果和净库存。早期 v0.5.1 存档没有主事人时 **不伪造过去的相识**。
3. **熟客**：同一位已知旅人至少两次由同一位居民实际接待，形成 1 条 `roadContact`，包含实际相识次数、接待者 ID、最后来访时间和来源记录。不能从随机文字凭空获信任。
4. **实际后果**：有了熟路，下一次沿山道来的客人，间隔从原先 12–16 村中日变为 10–14 日（并非增产或变出物资）；持续接客仍占用一位居民的劳动小时及约定的资源。玩家选择清静可停止新往来关系和额外的访客。
5. **观察**：村民检查可见接待履历、来客名称和真实劳动小时；茶棚检查/低频章节可看到具体熟客、回访和人情演变。活动时主事人确实在茶棚旁而非同时在林里伐木。
6. **保留 v4 槽位**：旧存档新字段无历史则按空状态迁移，不改人物秘密、不增加伪关系；只处理存在的正向事实。访客非居民，不能直接触发学徒、武功或强制门派结局。

## 验收
- 旧 104 项模拟和桌面/手机 v0.3/v0.4 回归保持通过；
- 同一固定种子至少出现一次由 **真实居民主事** 的接待与重复相识，姓名与住民 ID 稳定；没有住民/走不到茶棚则绝不交易；
- 给定相同资源/时间，是否有熟路实际影响下次访问间隔，不能只是 UI 字词；省略接待人不会免费换物；
- 读档/快进不重复招待/不重复积累熟客；篡改顾客 ID、人物或负交易差额被拒绝；
- 以稳态性能、浏览器截图和相同 seed 的移动端触摸为验收，不引入大规模 NPC 或单独游戏货币。

## 后续不在本轮
矿冶/护卫/学舍、亲属与战乱事件树、长期货车搬运、手工动画美术精修、低端 Android 性能正式达标。
