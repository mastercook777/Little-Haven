# 守望谷 v0.3｜微缩武侠山谷美术与表现升级规范

> 状态：美术设计规格，尚未实现。本轮不是追求写实 AAA，而是以**空间叙事、生活痕迹、动作可读性、四季天气**让玩家愿意停留观察。
> 参照：`.agents/skills/threejs-aaa-graphics-builder/`、`threejs-game-ui-designer/`、`threejs-qa-release/`。

## 1. 现有截图的具体问题

现有 v0.2 已明确是武侠山谷，保留柔和色调、正交视角、悬浮岛屿、酒肆与瓦房剪影。**优先处理：**

1. 大面积地表偏空，建筑像摆件放在统一底座上；生活活动缺乏围绕用途留下的道具。
2. 灰瓦屋顶与白墙组合重复，住宅尺度和屋檐高度相近，酒馆与普通房屋的主次还可以进一步拉开。
3. 山石较像背景排列，地势与建筑、路径之间缺乏“因地制宜”的层级；小桥与生活路线的叙事性不够强。
4. NPC 在默认缩放下辨识度偏弱；动作主要是腿臂摆动，缺少“坐、扫、搬、喝、练剑、抱拳”等职业动作。
5. 时间虽有动态灯光，但四季、降雨、修缮状态尚无可感知的画面差异。

这些是**当前截图与代码层的设计审计**，不代表已经完成运行帧率、实机动画或渲染指标的测量。

## 2. 风格定位与取舍

**风格：手工感 Low-poly 微缩模型 + 柔和 NPR（非真实感）渲染。** 参考东方山居的比例与材质语义，而不是贴上复杂仿古纹理。画面关键词：山路、酒旗、竹影、飞檐、烟火、旧瓦、清晨薄雾。

- 色盘：灰蓝瓦、暖木、米白墙、苔绿地、深竹绿；酒旗/灯笼为少量强调暖色。
- 主次：**酒馆第一视觉锚点**，竹林练武坪第二，桥与山门第三，居民生活点构成中景节奏。
- 视觉密度：细节堆在实际生活区域（檐下、门前、廊道、练武坪），场景边缘保持休息区；不要均匀撒小石块填满空白。
- 兼容当前可旋转正交相机和手机分辨率；任何细节都必须在默认镜头下仍可辨认，不能只在特写里成立。

## 3. 空间重构：一个有路径、有前后景、有生活核心的山谷

### 拟议分区

| 分区 | 结构 | 叙事职责 | 镜头检查 |
|---|---|---|---|
| **酒肆核心** | 二层灰瓦酒肆、檐下长凳、马桩、歇脚坪 | 旅人停留、人物相识 | 默认视角完整无遮挡 |
| **农居群** | 3–5 种屋顶/墙面变体、错落高差、围院 | 日常起居与劳作 | 门口有人出入，非等距排布 |
| **练武坪** | 木人桩、剑架、沙地磨损、竹阴 | 少年习武、未来收徒 | 训练动作可辨认 |
| **河桥山道** | 河床高差、石木桥、脚印路、山门 | 江湖从何处进入山谷 | 从山门到酒肆路线连续 |
| **竹林/山石** | 不等高体块、竹丛层次、远近树冠 | 隐居气质、季候可视 | 转动镜头不露明显穿插 |

**优先解决空间原因，再加装饰。** 不能为了一张固定角度截图，让房屋、路径、居民寻路互相穿插。

### 比例基准（设计值）

- 设成年人角色身高为 1，民居门高约 1.3–1.6；单层建筑檐高约 1.9–2.4。
- 酒肆轮廓在默认投影下应明显比普通民居醒目；优先多层、宽檐、前廊，而非简单把所有比例等比放大。
- 角色至少能辨识衣色/职业道具；桥净宽能容许对向行走，不让村民穿过栏杆。
- 建筑/Plot 设置遮挡检查，重要人物活动地点要有观测角度可达。

## 4. 可复用建筑 Kit（先代表切片，后扩展）

把现在 `home()`、`tavern()` 等独立几何组合拆成**屋基／墙面／屋顶／门窗／廊柱／附件／施工层／旧化层**。实例不应因局部替换重建整场景。

至少准备：

- 屋顶：单坡、双坡、错落双檐；瓦脊起翘、修补瓦、檐下风铃。
- 墙与木：暖白粉墙、旧木、柱梁、窗格、门槛；有新旧颜色和局部磨损的可控参数。
- 生活道具：柴堆、酒坛、扫帚、药架、篮筐、马桩、灯笼、晾晒、长凳、雨檐水桶。
- 阶段道具：施工木架/砖堆、补瓦木梯、修后瓦面、废弃长草。
- 剑庐/茶亭应从统一 Kit 演化，不是每个阶段临时写一种独立模型。

材质保留少量共享角色，风化用**局部 decals/材质参数/几何挂件**表达，避免共享材质被某一栋房屋改旧后所有建筑同时变旧。

## 5. 人物动画：从“摆动的棋子”到“有目的的生活”

当前角色使用程序化关节摆动是可以继承的基础，但需要**动作层 + 行为层 + 交互点**：

| 动作组 | P0 代表动作 | 后续 |
|---|---|---|
| 行走/待机 | 转身、站立呼吸、行走启停、走到目的地停止 | 避让、背包、登桥 |
| 劳作 | 扫地、搬柴/搬料、药圃采摘 | 提水、修屋、晒药 |
| 社交 | 抱拳、挥手、坐下喝茶 | 对话、围炉、叙旧 |
| 武侠 | 木剑练习两段、师父指点 | 对练、盘坐、回乡礼 |
| 天气 | 雨中快步、收伞/蓑衣 | 冬衣、护火、防风 |

实施契约：动作由模拟层 `activityId` / `interactionTargetId` 决定，渲染层只混合/播放；动作可中断、不能在下一帧骤然回默认姿态。道具拿在正确手上；人物脚底接触地面、旋转朝向匹配路径。初期使用分层程序化关节，而不是立刻上复杂人物骨骼或付费模型。

## 6. 季节/天气的场景语言

| 场景 | 主要可视信息 | 注意 |
|---|---|---|
| 春雨清晨 | 嫩竹、地面浅湿痕、屋檐滴雨、轻雾 | 不要用全屏白纱抹去建筑 |
| 夏日午后 | 丰绿、硬朗但柔和的阴影、晾晒、饮茶 | 高亮处仍保留瓦色层次 |
| 秋日傍晚 | 枯黄草梢、竹叶落片、暖低角度光、收获篮筐 | 与普通黄昏区分 |
| 冬日酒馆 | 冷蓝环境、薄雪或霜、暖窗灯、炉烟、厚衣 | 雪要有屋顶/地面附着，非仅粒子 |
| 大雾 / 雨夜 | 山道能见度降低、檐下聚集、局部灯火 | 降低粒子密度优先确保手机性能 |

引入 `EnvironmentVisualState`：`season` / `weather` / `daylight` / `buildingConditions`。**先状态，再视觉**，不要用浏览器随机数控制季节和房屋年龄。

## 7. 渲染与性能预算（基于仓库 Graphics Skill 的起点，非已测成绩）

- 模型优先“剪影→形体→材质→光照→微特效”，不追写实高面数。
- `InstancedMesh` 用于竹叶、碎石、重复瓦片/道具；复用 Geometry/Material，减少当前大量独立小 Mesh。
- 桌面参考：`renderer.info.render.calls ≤300`、`triangles ≤750k`、目标平均 60 FPS。
- 移动中端参考：draw calls ≤150、triangles ≤300k、目标 30 FPS；单阴影投射光、shadow map ≤1024、DPR 上限 1.5–2。
- 保持正交镜头，优先修正阴影接地、间接补光、颜色空间和雾；**首轮不要加入重型后处理链**。
- 所有天气粒子须有移动端降级、暂停清理和“减少动态效果”开关。
- 上述仅为预算/目标，必须用实际浏览器 `renderer.info`、性能分析和截图证明。

## 8. 交付顺序：两轮美术切片

**A · 山谷空间与建筑 Kit（P0）**
- 一张俯视布局图 + 可旋转真实场景；
- 只精修酒肆、相邻一户民居、练武坪和贯穿桥头的路；
- 代表性“新/旧/修葺”三种外观；
- 角色行走、扫地、练剑、抱拳四个可观察动作。

**B · 四季天气（P1）**
- 春夏秋冬四套环境视觉；
- 晴/雨/雾三种天气，首轮只做一种雨粒子与一套檐滴/地面湿痕；
- 季节驱动植被、建筑细节和部分行为；
- 中等性能手机的低粒子档位。

**未完成 A 前不要**同时扩展整片新地图、十几种天气或大规模生成 3D 素材。

## 9. 检查清单与验收

- 桌面默认镜头（1440×900）：初始夏日、春雨、秋傍晚、冬夜、酒肆修缮中、修缮完成、练武场动作。
- 移动竖屏（390×844）：同一事件仍能看到主酒馆与至少一个人物行动，HUD 不遮挡关键画面。
- 环绕检查：房屋穿模、树冠遮挡、屋顶/地形穿插、桥与河道连接、人物脚底接地。
- 动作检查：至少连续 4 秒观察行走/停步/工作/练剑，不出现手脚穿插和持续滑步。
- 在“相同相机+相同时间点”截图下，普通村民劳动前后必须有一处肉眼能察觉的环境变化。
- 亮度与视觉层次审计：整体不能只靠提高曝光、加雾、加 bloom 来伪装细致度。
- `npm run check`、`npm run test:sim`、`npm run build:pages`、浏览器控制台/画布非空检查；截图 + 性能实测通过后再合并发布。
