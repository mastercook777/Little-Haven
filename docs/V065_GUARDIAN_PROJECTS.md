# v0.6.5 · 守谷人议事簿（主动立项首个纵切片）

状态：开发分支，未验收。基线 main PR #34 / v0.6.4。保留 v0.6 存档、三人零建筑开局、经典模式和自治。

## 玩家循环
守谷人观察当前粮水、居民和在建工程，选择下一项村务，等待施工窗口，查看材料与真实工时，看到设施落成和既有生计机制改变。再根据缺口选下一项。无需守谷人在线或反复点击。没有新货币、强制任务或战斗。拒绝与失败不扣材料。

## 首轮选择
菜圃（有粮田需求，最多三块）、山居（人口未满、床位紧张）、木作棚（至少三处设施）、渔棚（至少一块菜圃）、粮仓（至少五人、两块菜圃、村心阶段二）、茶棚（八人、村心阶段三、七条路且已有粮仓或渔棚）。先有避雨棚。独特设施不可重复；共享原有地块、真实道路、材料、工时和生产结算。具体山居/木坊成本以勘地选中的原有形制为准。

## 状态与代价
同一时间一个玩家委托。选择后排队，不打断已经付费的工程。排队可撤回；已开工只能完成。乡邻优先保住饮水口粮和严重损坏设施；项目窗口打开后重新检查需求、存量和合法可达地块。勘地不通或需求消失则标明原因，允许重选，不冻结自治；本切片不新增开荒指令。正常施工扣实材，消耗排他的居民工时；项目 ID 绑定实际设施和守望录。完工状态来自真实建筑，不另发奖励。存档字段可选，旧 v6 档无委托即原样自治；重开、换槽独立。

## 验收
- 无棚禁用；有棚可选、忙碌可排队、不重复扣款、排队撤销不影响现有工程。
- 合法工程在正常逐时/流年下使用原有施工，实际建筑 causeId 匹配；存档恢复后委托与工时一致。
- 失败或取消不能生成设施；无委托时原模拟保持不变。
- 桌面/手机通过议事簿真实按钮选择、查看进度、完成，并检查旧谷不受影响。
- npm run test:sim、npm run check、npm run build:pages；浏览器与部署需独立验证。
