# 守望谷 · 众生命运系统（Living Fates）设计 v1

> 状态：**可供编码的系统规格；A/B 人物与共劳底座已在 PR #15 实现，C 的第一条「留种试田」纵切片正在 PR #16 验收，完整人物命运/外部世界尚未实现。** 其设计约束优先于批量生产剧情文本与随机高人。
>
> 产品前提：守望谷是**江湖中的村庄**，而不是默认的门派游戏。方向 B（特殊江湖势力）必须是少数人物长期互动的**可能后果**，不是玩家选择“发展路线 B”的菜单按钮。详见 [世界观圣经 v1](WORLD_BIBLE_V1.md)。
>
> 一句话：**生成一个人，不是生成一篇传记；他的经历必须通过真实行动、人与人的关系和可验证的世界后果，逐渐变成村庄的一部分。**

## 0. 第一版需要证明的纵向体验

一位新来的人看似普通 → 找到合法住所和生计 → 与他人多次共事/互助 → 某个现实问题唤起能力、旧事或一个新的抉择 → 他/她**实际花时间、用技能、冒风险**去行动 → 一条路/田地/工坊/他人的技能或安全发生持久变化 → 数年后可以反查“是谁、为什么、什么时候”。

**必须让“普通人的十年成长”与“偶然的隐藏高手出手”都成立。** 同一次模拟也可能什么秘密都没揭开，人依然能靠种田、教徒弟、修房屋改变村庄。

### 反面设计清单

1. `name + random class + rare bonus + 500 字身世`，却和当前世界没有接口；
2. 触发文本说“他修通了一条路”，实际图和 A* 均未新增有效道路；
3. 第 3 年自动揭晓人物隐藏身份，或“好感 100 必然拔剑”；
4. 身份一暴露永久成为无条件强力生产单位，无体力/疾病/风险；
5. 任意奇遇直接加 10 木材、凭空招来常住人口、跳过房屋碰撞；
6. 通过存档导入/快进/刷新可反复领取一次性角色收益；
7. 角色一死/离开，技能、建筑和历史都无影无踪，仿佛没来过。

## 1. 角色实体：可见身份、私人过往、行为证据分离

### 1.1 角色生成分六层

| 层级 | 必须存什么 | 规则 |
|---|---|---|
| **出身 `origin`** | 家乡来源类型、谋生经历、迁移动因、时代压力来源 | 与时间/外界局势/岗位/住房因果相容 |
| **表面身份 `public`** | 名字、职业自述、生活习惯、可见限制/技能 | 玩家只看见该知道的，身份描述不等于全部真相 |
| **过往 `private`** | 旧关系、历史经历的标签、隐秘技能、秘密保护理由 | 允许为空；即使存在也未必被发现 |
| **当前能力 `capabilities`** | 技能熟练度、体力、伤病/限制、价值倾向 | 从可证明岗位行为获得熟练，而不是“一段独白 +30” |
| **动机 `needs`** | 温饱、安全、尊严、牵挂、想做的事与忌讳 | 影响决策权重；若行为违背动机需要具体压力或成长 |
| **关系与命运 `social`** | 信任、共同经历、承诺/债、事件资格与改变 | 根据真实互动积累；秘密披露、改变职业、离去并非必然 |

### 1.2 v1 随机角色来源（六类）

| 原型 | 可观察身份/入口 | 可能携带的特殊经历 | 边界 |
|---|---|---|---|
| 农户与流民 `farmer_refugee` | 做饭、耕种、带亲属求落脚 | 灾年储粮、土壤经验、家人失散 | 不强制是无技术的“白板” |
| 行脚手艺人 `artisan` | 木匠、瓦工、修工具 | 旧主顾、稀有工艺、同门师兄弟 | 知识不能跳过工坊/原料 |
| 山野采集者 `herbalist` | 采药、识路、照护 | 郎中学徒、山村药方 | 不设万能治病、不造免费药物 |
| 旧日军伍 `soldier` | 护路、搬运、打猎、力工 | 斥候/逃散者/被解散的军士 | 旧兵不必是武学高手，可能讨厌暴力 |
| 商贾与脚夫 `trader` | 运货、计账、带消息 | 商路债务、旧交、商号经历 | 商贸必须有可到达路径和可交换商品 |
| 文士与学徒 `scholar` | 识字、记账、教习 | 游学、失意、读书家庭 | 学识须用教学、制度、记录行为体现 |

**所有原型可产出不同性别、年龄段与个性的人物。** 性别和出身可以影响时代背景中的处境，但不应被简化成“男擅长武、女只会做饭”的固定技能模板。

### 1.3 稀有度是背景权重，不是角色品质

建议起始权重普通 70% / 专业与特殊经历 25% / 江湖重背景 5%，**仅用于初版候选池平衡**；不是抽卡系统，也不应该给玩家显示“SSR”。

- 权重由历史年份、战乱/流民、路网可达、粮食、村庄待客倾向和空缺岗位调整。
- “江湖重背景”只是携带复杂社会联结的概率，不保证武功、不保证披露、不保证留村。
- 平凡角色也有 `lifeArc`，可因学习、救助、教育、师徒与长期劳动获得高影响力。
- 永远不能靠提高“高手刷新概率”替代建设医院、农田、客舍和人际关系。

### 1.4 固定锚点与生成边界

- 既有开荒三人 **梁伯、陆娘、阿禾** 保持 `id/name/role/homeBuildingId` 不变；给其新增故事元数据时使用“留白的可选线索”而非强制随机替换名字/身份。
- 现有迁居新人（小满、阿岚、叶生、青雀、孟石、阿荞）在已存在的存档中，姓名、ID、职业、住房、建设与已发生的日期**不得重抽**；迁入系统升级后，旧人物在补元数据时必须保留过去事实。
- 新迁居者先产生**带稳定 ID 的候选人**，再真实旅行/留宿/入户；不能在完成房屋时从数组里“现场刷新”一个无来源村民。
- 为居民与过客使用不同逻辑身份。只在迁居条件满足且双方都选择留下后转换 `visitor/candidate` → `resident`，不能按视觉人数计常住住房。

## 2. 能力的实现：四类首批具象技能

| `skillId` | 对应生活劳动 | 第一版具体数值/机制（待平衡） | 可见反馈 | 不能做什么 |
|---|---|---|---|---|
| `wayfinding` 识路勘道 | 探路、林缘清障、路线规划 | 困难地块勘测候选增加/路线搜索工作成本降低；**不直接生成无障碍路** | 实际施工调查者、勘路足迹、道路里程碑 | 跳过河道/屋檐/障碍碰撞 |
| `cultivation` 田间经验 | 播种、采收、留种 | 在**此人实际参与**田间劳动时改善某次农作的季节损耗/回补 | 地块产能与收成记录、学徒操作 | 无田无水免费产粮 |
| `healing` 诊疗护理 | 真实伤病后的照顾/采药 | 需要草药或时间，影响病者可工作的恢复进度 | 临时护理/药草架、病者恢复、事件记录 | 立即治愈所有病、复活死亡 |
| `protection` 护路应变 | 遇险、寻找失踪者、守护道路 | 在有真实威胁和当事人愿意承担时减少损失或提高救援概率，可能招来旧识 | 受损路段修缮、护路站、人物安全/名望变更 | 自动创建门派或无敌战斗 |

**选路试验**可作为第一条命运实际世界后果：熟悉山路的人提出一条候选路径；路仍须在 `pioneerPaths` 可走，村民在 `pioneerFrontier` 做实际清障，满足工时后才连通。若这套技术在 v0.4.4-C 尚未准备好，应先选“农田技艺传授”作为首个真实影响，不用假路动画充数。

## 3. 人际关系：从可记录行动积累，不从对话次数刷好感

### 3.1 数据结构

`RelationshipEdge` 使用有序 `min(id),max(id)` 的稳定双人键，值包括：
- `trust` 信任（建议 -100～100，按事实缓慢变化）；
- `closeness` 亲近（0～100，不能简单等同信任）； 
- `obligation` 有未履行承诺/互助债，带 `sourceEventIds` 和状态；
- `sharedWorkHours` 共同实际工作小时、`sharedMeals` 同席就餐次数；
- `memories` 少量重要经历的 ID，保留来源与当时日期；
- `tags` 可以是亲属、师徒、旧识、同伴、恩怨等，但**标签不得自动反推亲密**。

**第一版建议三种信任来源：同事共劳、实际互助、共同经历危险。** 同一小时某二人在相同工地且真的完成任务，才能算一次合作；只有两个模型在屏幕里站得近，并不能“刷交情”。

### 3.2 关系增长、遗忘与边界

- 常规日常同餐/共劳每个游戏日最多产生少量软关系变化，有递减收益，避免十天吃饭就成为生死之交。
- 显著关系必须由稀有的**可靠行动**产生，例如真挽救一次工程、分配过冬存粮、照护伤病。
- 信任可以降低/修复；争端可以存在，但不意味着自动成为反派或武侠仇杀。
- 长期关系可扩展为师徒、结义、邻里、亲子，**需额外的共同经历与双方意愿条件**；不能只有数值门槛就弹出“拜师成功”。
- 若对方离村/死亡，历史边仍留存为“旧识/故人”，但劳动角色不再参与实时调度；传承的技能与地图成果不删除。
- 性能：只维护有共同事件或居住邻近的稀疏边；九人初期可逐对，未来数十人不得做每帧完整两两配对。

### 3.3 记忆系统不是聊天记录

建议单个角色保留最近的轻量生活经历摘要与少量永久 `MajorMemory`，后者格式为 `eventId,minute,kind,actorIds,placeId,worldEffectIds,visibility`，有完整的实际来源。事件日志 `journal` 目前只保留 160 条，**重要人物履历必须独立于滚动日志**，否则十年后人物的过去会被每晚闲谈冲掉。

## 4. 何时揭示隐藏经历？

使用三重门槛而非“第 5 年必揭露”：

1. **环境契机**：当前存在与人物经历相关的真正问题，例如林路险阻、伤病、收留难民、工坊技术瓶颈；
2. **关系与动机**：当事人与至少一位相关人物有经历支撑的信任，或自身需求受到足够压力；他/她愿意采取行动；
3. **实际执行条件**：可抵达现场，劳动时间、物料、工具和基础安全均满足；失败时能解释原因并有恢复路径。

揭示可分级：`unknown → clue → suspected → confirmed → public`（并非每个人都需要走完）。**技能被使用可以部分显露，但不能强制揭示全部身份**。一位旧兵帮人识路，不等于全谷立刻知道他的全部军旅经历。

隐藏内容生成后存于**真相数据**；HUD、公开人物详情和普通守望录只取 `knownFacts`。调试模式可以检查真相但必须显著隔离，玩家UI和导出展示不能因引用原对象而意外剧透。玩家导出原始存档本身可查看原始数据：若以后提供剧情式导出，需选择是否包含剧透，不能声称源数据对拥有存档者保密。

## 5. 命运事件必须是可追踪的状态机

### 5.1 每个事件定义的合同

`FateArcDefinition` 应包括：
- `id/version/weight`；适用人群与 `origin,skill,tags`；
- `prerequisites(world,actor,relations,external)`：**纯函数**判断事实；
- `sourceFacts`：至少指出一条真实事件/工作/地点条件；
- `stages`：听闻 → 现实问题 → 人物抉择 → 实际劳动/代价 → 世界后果 → 长期回响；
- `branches`：至少两种合情合理的结果和一个不采取行动/条件不足的安全自治分支；
- `workOrders`：需要的岗位/路网/库存/时间，使用现有系统统一结算；
- `effects`：可识别的 `worldEffectIds`，**只由完成事务的模拟层产生一次**；
- `visibleEvidence`：详情、动画、设施、地块、生产数值或关系的至少一个长期证据；
- `cooldown/retry/terminal`：失败和再试边界；不能因刷新无限重复。

### 5.2 唯一事实、确定性与事务次序

1. 按统一 `world.minutes` 时钟推进工作/生命、天气、技能、关系、外部压力和命运资格；不得在渲染函数里触发事件。
2. 为每条事件链分配稳定 `arcInstanceId`、`actorId`、`createdAt` 和 `sourceEventIds`。
3. **准备阶段**：只提出意图、提示不确定性；不扣实际库存、不发放收益。
4. **执行阶段**：在居民已有日常工单调度前预留真实工时和资源；不得一个小时同时采粮、修屋、练剑和推进命运事件。
5. **完成阶段**：采用一次性 `effectId` 提交，原工单不可再结算；改变现有真实状态（农地产量、某段合法路、工具状态、人员工作能力或关系）。
6. **表现阶段**：Three.js 从结果读取模型/动作/路迹；日志记录角色、原因、地点与结果，不再更改模拟。
7. 导出/离线/重载/同种子多步进后，事件 ID、效果次数、资源、关系与图形的持久结果相同。

### 5.3 玩家建议只改变倾向

建议玩家控制为**一段村庄价值取向**（如避世/往来、守常/学新、自保/互助），未来可以对特定危机提出“一次低频建议”。守谷人不指定某人“立刻拔剑”，不会强制说出秘密；若无人回应或玩家未操作，系统仍沿角色的性格、关系、风险选择一个自治分支。

## 6. 第一批三条命运链（详规，可做测试种子）

### 链 A：山路与旧行脚者

- **适用**：山野、商路、军旅中拥有 `wayfinding` 的常住居民；可以是一位普通老樵夫，不能只让“隐藏高手”触发。
- **事实契机**：居民真实需要更远林地/外圈地块；主通道绕行较远、或部分地块待清障。
- **羁绊条件**：与清林劳动者一起工作过，或曾有互助记录；本人愿冒一次山路风险。
- **行动链**：提出候选新路 → 勘路实地劳动 → 新路 SAT/A* 安全、材料与清障工时达成 → 新段 `roadId` 登记，运输距离/效率实际变化。
- **分支 1**：信任高且可付出成本，则愿意带人开路，获实际替代路径。
- **分支 2**：选择隐居、不愿暴露或资源不足，则只提供安全路线建议/延后施工，村庄可走旧路继续生活。
- **长期回响**：道路与发起者关联；学徒通过陪同勘路获得小幅识路经验；若吸引商旅，外界也可能找到原本隐蔽的山谷。
- **严禁假实现**：仅凭人物有 `wayfinding=80` 就在地图凭空画出新路。

### 链 B：一块田与留下的种子

- **适用**：普通农户、山野采集者；无需秘密身份。
- **事实契机**：季节低产、实际多日同田劳动、有人愿意向资深农人学习。
- **行动链**：选择一块真实 `garden` → 留种/试种（短期少收）→ 两人实际共劳 → 来季产能微调或变差 → 记录原因和结果。
- **分支 1**：准备充足且天气适配，出现可持久的作物管理经验，减小以后风险。
- **分支 2**：留种期间缺粮，被迫中止，可能影响两人关系但不清空整块田；以后仍可再试。
- **长期回响**：学徒掌握一项初级田间技能；原人物年老离去后，该地块的经验和村民技能仍然保留。
- **验收重点**：两种分支都真实改变田地数据/粮仓/工时，没有免费粮食、没有一次性文本硬加库存。

### 链 C：伤者、旧兵与选择

- **适用**：曾受伤的军旅人物或有 `healing/protection` 的普通住民，事件主角可以是施救者而非旧兵本人。
- **事实契机**：来自外界的真实伤者抵达、有效居住/护理地点与余粮；若医疗模型未落地，不提前启用此链。
- **行动链**：受伤→实际停工/疗养与物资成本→有人持续照护→可能触及旧身份顾虑→被照顾者恢复、离去或选择定居。
- **分支 1**：收留成功，旅人可能成为未来工匠/教师，但仍需独立迁居条件；
- **分支 2**：资源不足时由村民提供短暂护理后帮助其离开，而非强制把难民留下饿死；
- **分支 3**：某人为了保护大家公开旧身份，可减轻伤害，但提高 `jianghuAttention`，带来后续追寻风险。
- **长期回响**：救助记录、关系与部分设施/护理使用痕迹保留；无法医治者也应有克制的结果，不用免费神技兜底。
- **安全产品边界**：不将严重创伤写成日常乐趣或“抽到稀有侠客”的奖励机制。

## 7. 方向 B 如何自然产生，又如何避免劫持全局？

`SettlementIdentity` 建议可叠加以下标签：`homestead`、`woodland_craft`、`river_trade`、`refuge`、`waystation`、`martial_apprenticeship`、`mutual_defense` 等。标签描述实际生活形态，**不是门派升阶树**。

`martial_apprenticeship` 出现至少需要：
- 相关人物长期常住且**实际愿意传授**；
- 至少两位有稳定共同学习/信任经历的居民愿意参与；
- 有合法的真实训练位置、可支出的工时和不危及温饱的资源；
- 周围的社会需要和外部压力足以解释为什么兴办；
- 前期保护好普通人的生活，不因一位强者入谷就把农户自动变弟子。

即使符合条件，也允许出现：隐秘一对一授艺、互助护路队、简陋练武坪、对外开放的小社，或干脆拒绝；**不得把“创立门派”作为达成胜利的必要条件**。人员离去、信誉变化、连续亏粮时训练活动可以停办，村庄仍是可生活的村庄。

## 8. 代码/存档集成草案（类型仅为设计合同，不是现有实现）

现有基础事实：
- `src/simulation/pioneerWorld.ts` 中 `PioneerFounder` 含 `id:number, name, role, activity, target, homeBuildingId, commute`，`PioneerWorld.founders` 是常住居民权威表；
- `src/simulation/pioneerGrowth.ts:considerPioneerMigration` 目前使用六名固定候选姓名，真正迁入受房屋、粮、水与农田限制；
- `PioneerJournal` 有 `id,minute,title,text,causeId`，最多保存 160 条，不能直接用它承载永久人物履历；
- `pioneerCommons.ts`、`pioneerFrontier.ts` 已实现真正工时/资源/清林事件，命运结果需要**复用它们的单次结算和地块检查**，不能另造无成本捷径。

建议新增模块（可以与源代码实际调整，但要保证职责）：
- `simulation/livingFates/characterGenerator.ts`：以 `seed+residentId+arrivalContext` 稳定生成公共资料与私有经历，含组合排除规则；
- `simulation/livingFates/peopleState.ts`：`PersonLife` 稀疏附属表、能力、人生记忆、公开程度与状态迁移；
- `simulation/livingFates/relationships.ts`：关系边、共事/互助事实、日结衰减与长期记忆；
- `simulation/livingFates/worldPressure.ts`：历史年份与战乱、商路、江湖关注的独立外部条件；不需要后端；
- `simulation/livingFates/fateEngine.ts`：条件资格、命运状态机、工单调度、一致性和重复效果保护；
- `simulation/livingFates/fateArcs.ts`：少量可重组的规则/文案模板，不在此处直接修改库存或房屋；
- `ui/peopleInspection.ts`：只读取允许公开的 `knownFacts` 和已发生的历史；
- `graphics/`：依据 `work`、`effectId` 与角色行为驱动姿态和长期地景，不能改世界事实。

### 8.1 建议 TypeScript 轮廓

```ts
type PersonId = number;                 // 复用 PioneerFounder.id
type TruthVisibility = 'unknown'|'clue'|'suspected'|'confirmed'|'public';

interface PersonLife {
 residentId: PersonId;
 generatorVersion: 1;
 origin: 'farmer_refugee'|'artisan'|'herbalist'|'soldier'|'trader'|'scholar';
 publicFacts: { arrivalReason: string; habits: string[]; knownSkills: string[] };
 privateFacts: { tags: string[]; secretSkills: string[] };
 knownTruth: Record<string,TruthVisibility>;
 motivation: { safety: number; belonging: number; responsibility: number };
 skills: Record<string,{ level:number; xp:number; lastPracticeAt:number }>;
 majorMemoryIds: string[];
 arrivalAt: number;
 state: 'resident'|'away'|'departed'|'deceased';
}
interface RelationshipEdge {
 id: string; a: PersonId; b: PersonId;
 trust: number; closeness: number;
 sharedWorkHours: number; sharedMeals: number;
 memoryIds: string[]; obligationIds: string[];
}
interface FateArcInstance {
 id: string; arcId: string; arcVersion: number; actorIds: PersonId[];
 phase: 'latent'|'offered'|'working'|'resolved'|'abandoned';
 createdAt: number; sourceEventIds: number[];
 branchId?: string; appliedEffectIds: string[];
}
interface LivingFatesState {
 schemaVersion: 1; people: Record<string,PersonLife>;
 relationships: RelationshipEdge[];
 majorMemories: Record<string,{
  id:string; minute:number; actorIds:PersonId[]; sourceEventIds:number[];
  placeId?:string; effectIds:string[]; visibility:TruthVisibility }>;
 arcs: FateArcInstance[];
 appliedEffectIds: string[];
 external: { war:number; displacement:number; roadAccess:number;
  authority:number; jianghuAttention:number; trade:number };
}
```

**注意：** 不把 `PioneerFounder` 完全替换为 `PersonLife`。保持 `founders` 作为劳动/住房/人口的权威数组，`life.people` 使用同一 `residentId` 作为**附属人物资料**，通过 ID 关联；不得出现两份常住人数、两份住房或双重食品消费。未来可演化为统一 Entity Store，但**v0.4.4 不为此重构所有建筑与寻路模块**。

### 8.2 存档迁移与历史兼容硬约束

- 先为旧 v4 存档添加**可缺省**的 `livingFates`；旧档解析后通过确定性迁移构建 v1 附属资料。维持 `PIONEER_SLOT_KEYS` 原槽名，经典 `v3` 不受影响。
- 既有居民：固定 `id/name/role/homeBuildingId`，不改以前的 `journal`、房屋、道路、树、村心和材料，也不倒填“他 5 年前救过人”的虚构记忆。
- 已迁入者的公开资料可由现有 `role` 与迁入日期生成合理的**初始可见基础**，不可把新设计默认当作其过往已发生的事实。
- 隐秘随机数以 `world.seed + residentId + generatorVersion` 等稳定组合计算并立即持久保存。**不能每次读取存档重新随机一次身份**，更不能依赖随步进次数改变顺序的全局随机流。
- 新候选人必须先固化为具 ID 的候选实例，之后按真实房屋与粮水决定能否迁居；旧六个固定迁入者不会因新池上线被改名。
- 存档验证须检查稳定/唯一 ID、已应用效果不重复、关系双方存在于角色历史、事件时间不晚于当前世界、状态与正在工作工单无冲突；畸形数据拒绝或安全回退，不允许凭空资产。
- 快进/offline 与逐小时推进应产生相同结果；经济与世界事件可采用天/小时两个统一结算点，但不可由 UI 帧率决定。

## 9. 最小可实现里程碑（v0.4.4 分四步）

| 切片 | 实作范围 | 自动验收与人眼检验 |
|---|---|---|
| **A：生成一个可信的人** | 固定三人 + 新移民组合原型、公开/隐秘资料、稳定随机、存档迁移与防剧透详情 | 6 类原型可被确定性生成，4 类技能有现实岗位关联；同种子同时间/刷新/离线一致；旧九人存档姓名、住房与粮不变 |
| **B：让邻里真的有羁绊** | 共劳、救助、共同用餐、信任/关系边/记忆与初步技能成长 | 无共事不凭空涨关系；事件因真实劳动得分；四年相熟仍不会自动触发隐藏高手；历史不被 160 条日记冲掉 |
| **C：让命运改变世界** | 完成链 A/B/C 中**一条**有分叉、未达成/已达成状态与可见后果的完整纵切片 | 至少 1 位人物通过真实工时/资源永久改变一块地/道路/作物与他人关系；保存重读不双重奖励，文本说到与地图真正一致 |
| **D：与发展图谱连接** | 低频村庄气质、外部来客/候选权重、里程碑/物流入口 | 不选择照样持续发展；普通村线和少数武学支线都可出现，且武学支线不劫持住房粮食与本体玩法 |

### v1 推荐测试矩阵

- 种子：固定回归 `42`、与其不同的 2–3 个种子；同 seed 改村庄政策；至少一例普通人高影响与一例江湖背景但最终隐居。
- 时间：新档第 1 天、第 1 年、第 4 年、第 10 年；`1×/流年/offline/导入` 等价，关系与事件不存在状态漂移。
- 人口：三开荒者固定、多个迁居者、访客不算常住、离村后历史保留、双槽切换不交叉。
- 经济：路、地、房与食物约束仍有效；一位村民一个小时最多一项收费劳动；没有技能凭空生出木材/粮食。
- UI：未知秘密不剧透，玩家可从具体人物、事件、地块跳查因果；移动端简短且不遮满微缩谷。
- 行为：单一故人触发多种后续概率与条件，但不会必然成为门派；无角色事件时普通农业村依旧可以长期游玩。

## 10. 关键风险与制动

| 风险 | 制动 |
|---|---|
| 任意随机组合变荒诞履历 | 基于起源、时代与技能的条件生成和冲突排除；保留“平凡”的空秘密 |
| 按年发剧情，程序感强 | 时间只是外界压力，事件必须有真实地点、人际、岗位与需求 |
| 隐藏高手喧宾夺主 | 极低背景权重 + 独立披露意愿 + 生活优先，不会直接给最强职业 |
| 社交刷数值、玩家抽卡 | 关系由共劳/互助等证据，玩家只调谷中价值取向 |
| 负面事件摧毁多年存档 | 可预警、有自治补救、恢复路径，避免单次无法挽回的全村灭绝 |
| 性能随人口二次增长 | 附属表 + 稀疏关系图 + 日结/小时结，不在渲染帧 O(n²) 更新 |
| 信息泄露/故事穿帮 | 私密真相与公开事实隔离，日志只写已观察/披露内容，生成器版本固定 |
| 人物事件绕过真实经济 | 所有世界效果复用工单和现有资源/地块/道路接口，effectId 幂等 |

**最终验收句：十年后，指向一条路、一块田或一位徒弟，系统必须能回答——谁来到这里、与谁相识、在什么情况下做出过什么行动，以及为什么世界从此不同。**
