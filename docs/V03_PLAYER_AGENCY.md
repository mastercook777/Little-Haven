# 守望谷 v0.3｜守谷人的参与感与机缘系统

> 状态：设计规格，尚未实现。主旨：**不直接指挥居民，但玩家的每一次出手，都能留下可追溯且可看见的影响。**
> 关联：`docs/V03_WORLD_FRAMEWORK.md` / `docs/V03_VILLAGE_GROWTH.md`。

## 1. 问题定义

v0.2 只有一次 `host/observe` 选择；当 `storyStage='legacy'` 后，信箱变成“旧事”，世界基本不再向玩家提出参与机会。故事阈值又是以分钟为单位的连续推进，错过分支后的复盘能力不足。

v0.3 不能用“给村民下任务、点建筑升级、赚金币”填补空白：这会破坏守谷人身份。必须设计可持续、低频、能被观察的“机缘”。

## 2. 参与模型与核心循环

**观察 → 发现需求/征兆 → 选择是否创造机缘 → 居民自己行动 → 世界留下痕迹 → 守望录回溯。**

- **玩家能影响**：支持哪个心愿、缓解哪项困难、为谁提供相遇机会、倾向何种谷中风气。
- **玩家不能控制**：某人一定拜师、谁嫁给谁、某位游侠必胜、建筑立刻完成、居民必须照办。
- **无操作也有世界**：居民每天工作、社交、修缮；未回应的机缘自动走一条有依据的路线。
- **不是无限签到**：新机会来自世界条件，不因每次点击而凭空产出数值。

## 3. 四种守护行动（v0.3 仅先实现前两类）

| 类别 | 触发 | 玩家行为 | 可能影响 | 最小可视反馈 |
|---|---|---|---|---|
| **结缘** | 旅人留宿、少年愿望、两人相识 | 留一盏灯、传递书信、促成相遇 | 师徒、友情、招待、传闻 | 两人驻足交谈/酒馆亮灯 |
| **庇护** | 房屋待修、雨季临近、乡民缺料 | 提供木材、祝福收成、协调互助 | 工程优先级、恢复效率、安全感 | 村民搬料、脚手架、修补瓦片 |
| **导风**（v0.4） | 村庄稳定发展 | 鼓励尚武/经商/济人/隐居 | 未来数季的行为偏好与访客类型 | 酒幌、练武坪、药圃等细节变化 |
| **抉择**（v0.4） | 官差征税、匪徒探路、难民借宿 | 在两个有代价的方案中选择 | 物资、安定、名声、人际关系 | 巡逻、护栏、灯火、居民聚集 |

每次选择至少产生 **1 个当下动作反馈 + 1 个持续状态变化**；禁止只弹出一段文字并把资源 +10。

## 4. 决策形式

建议纯模拟 schema：

```ts
type InterventionKind = 'bond'|'shelter'|'culture'|'dilemma';
interface Opportunity {
  id:string; kind:InterventionKind; createdAtMinutes:number;
  subjectIds:number[]; buildingIds:string[];
  causeIds:string[]; deadlineMinutes:number|null;
  options:{id:string; label:string; preview:string; hint:string}[];
  defaultOutcomeId:string;
  state:'available'|'resolved'|'expired';
}
interface GuardianMemory {
  opportunityId:string; chosenOptionId:string;
  resolvedAtMinutes:number; automatic:boolean;
  producedEventIds:string[];
}
```

- 来源是 NPC 需求、关系、建筑状态与天气预报，不按固定日期无脑刷新。
- UI 默认同时最多 **2 张未处理重要机缘**，超过时汇总为“谷中尚有消息”而非覆盖画面。
- 普通支持行为尽量**不消耗抽象能量点**；如需节制频率，优先采用“每季一次重大祝福 + 若干不限制次数的小观察”。这些是体验预算，而不是付费资源。
- 玩家可以选择 **支持 A / 支持 B / 暂不干预**，第三个选项不是“失败”；自动发展不能与有意不干预混淆，日志记录 `automatic`。
- 对分歧进行**倾向性而非保证性**描述（“提高师徒相识的机会”），避免虚假承诺。

## 5. 三个可验证的参与案例

### A. 无名酒肆的雨夜客人

前提：小雨、酒馆营业、沈问舟入谷。选择：留客一宿 / 提供路引 / 随缘。居民后续：陆娘添炉火，旅人借宿，少年可能相遇。视觉：灯火延长、伞立门旁、酒坛与座椅使用率变化。可回溯：事件标明“因为雨夜留客”。

### B. 酒馆旧屋檐

前提：酒馆 `conditionScore<55`、春雨频繁、村民有修缮需求。选择：资助补瓦 / 优先修排水 / 由居民自行安排。后续：木匠取材、分天施工、屋顶换瓦。长期区别：补瓦降低磨损，排水降低雨季损耗；不参与也会有较慢的自治修缮。

### C. 练武少年与竹林空地

前提：阿青已长期练习且练武坪使用率高。选择：支持建剑架 / 支持给少年留一块安静空地 / 不干涉。后续：小七协助搬木料、阿青使用新器具；若后来有人收徒，剑架可成为剑庐建设的条件之一。**不允许选择后立刻生成门派。**

## 6. 后果、危机与公平

- 重大危机须有“传闻/征兆 → 准备窗口 → 结果 → 恢复”四段；不得在离线时无预警地灭村。
- 失败/遗憾可产生新的故事（旅人离开、工程延期、关系疏远），但不清除玩家投入的整个世界。
- 机缘可能相互影响，必须有因果 ID；避免随机事件覆盖前一个选择。
- 守谷人拥有**悔棋的不是回档按钮，而是新开档/多存档槽**：允许体验其他分支，但每个槽的因果历史应保持一致。

## 7. UI 原则

沿用当前“江湖风闻 + 守望录 + 底部时间控制”布局，不用厚重大面板遮挡村景。

- 右侧卡：谁在提出需求、为什么现在发生、最多三项选择、可预期的短期反馈、截止日（如有）。
- 点击 NPC/建筑：展示“正在做什么／为什么／下一步可能是什么／与过去事件的联系”，只读不指挥。
- 选择后立即看到局部场景反应（角色转向、灯火、搬料等）；较长期变化进入“下一季预告”。
- 一季回顾：优先显示 **3–5 条真实变化**，不要重复“晨雾散去”灌水。
- 新开档按钮与导出/导入存档必须明确，未来不同村庄可并行保存，避免 v0.2 不能试第二分支的问题。

## 8. 实施与验收

**第一阶段 P0：** 酒馆修缮援助 + 雨夜留客，两种可重复但不刷屏的 Opportunity，保留阿青 v0.2 故事作为背景历史。

测试合同：
1. 只有具备前提才出现机缘；重复读档不复制、重复点击不重复结算。
2. 三种选择都能推动世界，`automatic` 不阻断自治。
3. 同步/快进/离线收敛；无预警的离线危机不会直接摧毁建筑。
4. 至少两处可见结果（如灯笼亮度、屋顶修补）与对应的事件 ID 可以互相反查。
5. 单屏默认视角能看见场景变化，移动屏的按钮可点且文本不会溢出。
6. 一次守谷操作不应替代居民的后续劳动。

**不做**：抽卡、付费加速、玩家操控战斗、无穷无尽的任务板、实时 AI 文本聊天。
