# Little Haven v0.1 — Game design brief

## Player promise

看到一座微缩山谷在没有你持续指挥的情况下自己运转；你所回应的一次愿望，会让世界留下持久且可见的痕迹。

## Desired feelings

安静好奇 → 轻轻牵挂 → 见证变化 → 想再回来看看。

## Core-loop contract

1. **观察**：缩放和旋转村庄，观察不同居民在工作、散步、交流。
2. **感知**：右侧「守护者的信箱」带来一次村民提议。
3. **干预**：选择支持木桥或花园，锁定一个有取舍的发展方向。
4. **生长**：施工现场随模拟进度变化。时间可以加速或暂停。
5. **见证**：完成后 3D 场景出现对应设施、居民人数增加、幸福感变化、居民路径变化，并记录在编年史中。
6. **再观察**：玩家探索为什么世界变成了现在的样子。

## Representative first-session plan

- 前 20 秒：看到完整村庄，发现风车、河流、农田、集市和活跃的居民。
- 20–60 秒：旋转镜头、放大村庄、点击一位居民，查看其职业和当前行动。
- 接下来约 45 秒：选定木桥或花园，看到建设进度。
- 再花 20 秒：观察新增设施、新的居民，打开编年史。

## Mechanics

| 系统 | Prototype v0.1 |
| --- | --- |
| 生活日程 | 每位居民有家庭、工作地点、出行、闲聊/散步和休息时间段；不同 offset 调整节奏。 |
| 世界时间 | 1× 时 240 真实秒 / 游戏日；4× 和 12× 可加速。 |
| 人口 | 初始 8，事件完成 10。 |
| 干预事件 | 1 次永久分支：桥（探索）或花园（社交）。 |
| 视图 | 正交相机、旋转/缩放、选中居民。 |
| 记录 | 开始、选择、完成和每日清晨均写入编年史。 |
| 存档 | 本地存储、页面后台恢复和离线补偿上限。 |

## Design risks

- 城镇目前没有真实的建筑自主增长和完整的环境经济，连续可玩的深度较短。
- 道路是固定地表模型，不会由真实流量自动长出。
- 复杂关系和个体记忆尚未实现；故事当前使用规则/固定文本，不接入大模型。
- 居民行走采用插值的日程路点，而非可避障寻路。

## Next validated vertical slice

在玩家认为 v0.1 的微缩观赏感成立后，实现完整的短循环：资源形成 → 居民提出建设 → 守护者批准 → 施工 → 新职业/新行为 → 下一封信。不要提前扩充地图或种类。
